## 1. 问题

自动打怪开启后是**无脑定频空放**：`configs/MapleFarmTask.json:16` 与 `src/task/MapleFarmTask.py:27` 的 `攻击模式` 默认值都是 `定频`，主循环走 `MapleFarmTask.py:166-168` 的分支，不看画面里有没有怪。

用户要求：**攻击区内有怪才放技能；没怪就停手**。

「停止」的语义已确认：**只停手不放技能，任务继续运行**（保命、喝药、守卫、拾取全部照常）。怪回来自动恢复攻击，不需要手动重开。

## 3. 实测证据

本节全部为 2026-08-06 本次实测，数据源：`screenshots/test_frames/training_ground_full_2560x1440.png`（1 帧）与 `dataset/images/train/map1_frame_00XX.png`（40 帧，训练集）。探针脚本在会话 scratchpad，未入库。

### 3.1 角色定位手段筛选

| 手段 | 实测结果 | 判定 |
|---|---|---|

| **中央区分块 OCR（x 0.35-0.65 / y 0.40-0.70，640×240 重叠 200）** | **中位 118ms、最大 235ms，12 块** | ✅ 采纳 |
| 名字牌模板匹配（彩色） | 跨 100 帧中位分 0.719，最佳位置飘到 x[146,2350] y[285,1384] | ❌ 底框半透明，模板吃进地图背景 |

### 3.2 名字牌 OCR 的三种质量（40 帧，中央区）

匹配子串命中率：`Yufeng咕咕` 22/40 → `Yufeng` 26/40 → `咕咕` 30/40 → `咕` 32/40。

但命中分三类，**框宽是干净的判别特征**：

| 类型 | 实测样本 | 框宽 | 锚点可信度 |
|---|---|---|---|
| 干净 | `Yufeng咕咕` | 120-130px | ✅ 准 |
| 被宠物牌截断 | `ng咕咕`、`ufeng咕咕`、`咕咕` | 58-114px | ⚠️ 中心右偏 |
| 与邻牌粘连 | `小白雪人ifeng咕咕`、`等级4木奶小白雪人ufeng咕咕` | 171-**324px** | ❌ 锚点偏出 100-200px |

漏检根因已定位：**宠物名字牌遮挡角色名字牌**（`map1_frame_0009` 里角色名只剩 `ng咕咕`，前半被「小白雪人」压住）。宠物常驻跟随，这是系统性遮挡，不是偶发。

### 3.3 其他已确认事实

- 名字牌**渲染在角色脚下、大致水平居中**，白字 + 半透明深色底框
- 同平台站桩时**名字牌 y 极稳定**：40 帧里 y 全为 887-888（换平台时才变，另见 738 / 783）
- 角色 x 落在 **1073-1468**（画面中心 1280 ± 200），符合「相机跟随角色」
- 中央搜索区**天然排除两个同名干扰源**：右侧组队列表（x≈2303, y≈1032）与左下角状态栏（x≈732, y≈1421），二者都在 x 0.35-0.65 / y 0.40-0.70 之外
- 任务级配置支持下拉：`{'type': 'drop_down', 'options': [...]}`（`ok/gui/tasks/ConfigItemFactory.py:35-41`）
- YOLO 找怪 22ms/帧、val mAP50 0.895（上游 spec §8 M3，已验证）

- **攻击区宽 600px 是否等于魔法师技能真实射程**：§3.5 的标定图只证明它没有跨平台乱框、正确纳入了同平台右侧一只怪——这是像素级的合理性检查，不是射程验证，**脚本证明不了这件事**，继续待 §7.3 判据 F 实弹验证。
- **游戏是否有「关闭宠物名字显示」选项**：若有，3.2 的遮挡整类消失，干净锚点率应大幅上升。未确认，不作为设计前提。
- **角色是否可能长期偏离中央区**（地图边缘站桩、相机夹取）：未测。设计上由「过期回退到屏幕中心」兜底。

## 4. 设计

### 4.1 判定链

每个攻击节拍（`攻击间隔(秒)`，默认 1.5s）执行：

```
取角色锚点 → 算攻击区 → YOLO 找怪 → 有怪中心落区内?
                                      ├─ 是 → 发攻击键
                                      └─ 否 → 停手（不发键，任务继续）
```

保命/喝药/死亡判定/守卫全部在攻击之前执行，本次改动**不触碰**这些分支。

### 4.2 锚点获取（两级 + 回退阶梯）

只在攻击节拍上跑，不占 10Hz 触发循环。

1. **快通道**：上次锚点周围 ±240×±80 的小窗 OCR。**已实测**（2026-08-06，`dataset/images/train/map1_frame_0000.png`，已知锚点 `(1211, 888)`，`prewarm()` 预热后连续调用 `anchor.find_in_window(frame, 'Yufeng咕咕', (1211, 888), 240, 80)` 5 次，5 次均命中）：首次调用 53.6ms，之后 4 次 8.8-10.4ms，**中位 9.4ms、最大 53.6ms**；重跑一轮复现一致（中位 8.5ms、最大 50.2ms）。首次偏慢是 OpenVINO 对该输入形状的首次编图开销（`prewarm()` 只装载模型权重，不会预跑这个具体窗口尺寸），只发生一次，不是 §3.1 记的 280×55 ROI 那次 35ms 里包含的模型加载耗时的重演。稳态耗时（~9ms）反而低于 §3.1 的 35ms，推测两次测量条件不同（ROI 尺寸、机器状态），不作进一步解释
2. **慢通道**：快通道失败时，中央区分块扫描（实测中位 118ms）。独立节流，最快 `锚点刷新间隔(秒)`（默认 2s）一次
3. **沿用**：都没拿到 → 用上次锚点，只要其年龄 ≤ `锚点保鲜(秒)`（默认 10s）
4. **回退**：锚点过期 → 用**屏幕中心**当锚点，记 warning（最多每 60s 一条，防刷屏）

任何一级都**不停任务** —— 用户明确要求只停手。

### 4.3 锚点收货判据（写死）

中央区/小窗内的 OCR 结果，**只接受 `strip()` 后与配置的「角色名」完全相等的文本框**。

- 更长（粘连，如 `小白雪人ifeng咕咕`）→ 丢弃，记 debug 日志
- 更短（截断，如 `ng咕咕`）→ 丢弃
- 理由：3.2 的实测显示粘连会把锚点带偏 100-200px，而干净命中率 22/40 ≈ 55% 已足够 —— 站桩时角色不动，配合 4.2 的沿用/回退，2s 刷新一次里平均 1.8 次就能拿到一个干净锚点

锚点坐标 = 该文本框中心。

### 4.4 攻击区

- 角色身体中心 = 锚点 **上移** `名字牌到身体偏移(像素)`（默认 90，§3.5 已实测几何中心偏移 ≈83px，默认值仍在角色轮廓内，保留不改）
- 攻击区 = 以身体中心为心的矩形，`攻击区宽(像素)` × `攻击区高(像素)`，**左右对称**（不做朝向，已确认）
- 判定：怪物检测框**中心**落入矩形即视为可攻击
- 单位从画面比例改为**像素**（1440p 下标定，主循环已有帧尺寸守卫锁死 2560×1440，不需要缩放换算）

### 4.5 配置变更

新增：

| 键 | 默认 | 说明 |
|---|---|---|
| `角色名` | `''` | 名字牌 OCR 的匹配目标。留空 → 检测模式退化为屏幕中心锚点 |
| `攻击区宽(像素)` | 600 | §3.5 标定图验证未跨平台乱框，是否等于真实技能射程待 §7.3 判据 F 实弹验证 |
| `攻击区高(像素)` | 200 | §3.5 标定图已验证合理（罩住帽顶到脚底并留余量，正确排除上下层平台的怪） |
| `名字牌到身体偏移(像素)` | 90 | §3.5 已实测几何中心偏移 ≈83px，默认 90 落在角色轮廓内，保留不改 |
| `锚点搜索区宽(比例)` | 0.30 | 横向以屏幕中心为心 |
| `锚点搜索区高(比例)` | 0.30 | 纵向以下一行的中心为心 |
| `锚点搜索区中心Y(比例)` | 0.55 | **不是 0.5**：名字牌画在角色脚下，相机对准的却是身体，牌子系统性偏在画面中心下方（实测 y ∈ [738, 888]，中心 813 > 720）。0.30/0.30/0.55 合起来正好等于 §3.1 实测基线所用区域（x 0.35-0.65 / y 0.40-0.70）；改这三个值中的任何一个都等于换了区域，§7.2 的基线必须重测 |
| `锚点刷新间隔(秒)` | 2 | 慢通道节流 |
| `锚点保鲜(秒)` | 10 | 超时回退到屏幕中心 |

删除：`攻击区宽`、`攻击区高`、`攻击区中心X`、`攻击区中心Y`（比例制，被 4.4 取代）。`configs/MapleFarmTask.json` 里残留的旧键无害，框架按 `default_config` 取值。

变更：`攻击模式` 默认值 `定频` → `检测`；注册 `config_type = {'攻击模式': {'type': 'drop_down', 'options': ['定频', '检测']}}`。

### 4.6 性能预算

单个攻击节拍最坏 = 快通道（实测见 4.2，最大 53.6ms，绝大多数情况下走这一级）+ 慢通道 235ms（快通道未命中时才会额外跑）+ YOLO 22ms。

- 快通道命中（多数节拍）：稳态 9.4ms + YOLO 22ms ≈ 31.4ms，占 1.5s 节拍的 2%。
- 快通道未命中、回退慢通道（少数节拍）：最坏按快通道 53.6ms + 慢通道 235ms + YOLO 22ms ≈ 310.6ms，占节拍的 21%；10Hz 主循环被阻塞同样时长，即保命判定最坏延迟 ≈0.31s。

相对 `保命血线` 的响应窗口应可接受，但**这是单帧静态测量的推断，不是结论** —— 由 §7.3 判据 H 实弹确认。若实测超标，退路是把慢通道挪出主循环（后台线程只更新锚点）。

## 6. 标定工具

`scripts/calibrate_attack_zone.py`：读一张帧（默认取最新截图，可传路径），跑锚点识别，输出一张标注图 —— 画出识别到的名字牌框、推算的身体中心、当前配置下的攻击区矩形，并把 YOLO 检出的怪框一并画上，标注每只怪「在区内 / 区外」。

用途：用户看图直接调 `攻击区宽/高(像素)` 和 `名字牌到身体偏移(像素)`，不再手算画面比例（README 现在要求的做法）。

## 7. 验证计划（判据事先写死）

### 7.1 离线单测（`tests/test_farm_logic.py`、`tests/test_farm_task_offline.py`）

- 怪中心在区内 → 发攻击键；在区外 → 不发；边界值（正好落在边上）→ 发
- 锚点收货：文本恰等于角色名 → 收；更长（粘连）→ 拒；更短（截断）→ 拒
- 锚点过期：年龄 > `锚点保鲜(秒)` → 回退屏幕中心；年龄内 → 沿用
- 检测模式 + 无怪 → `send_key` 未被调用，且 `stop_farming` 未被调用（**任务不停**）
- `角色名` 留空 → 不跑 OCR，直接用屏幕中心锚点

### 7.2 帧回归（`tests/test_anchor_offline.py`，数据源 `dataset/images/train` 前 40 帧）

通过判据（基于 §3 实测基线，事先写死）：

- **A**：干净锚点命中 ≥ 20/40（实测基线 22/40）
- **B**：所有命中帧的锚点 y ∈ [700, 950]（实测 738-888）
- **C**：无一帧返回框宽 > 160px 的粘连结果（粘连必须被 4.3 的判据挡掉）
- **D**：单帧中央区扫描耗时 ≤ 400ms（实测中位 118、最大 235）。**计时前必须预热 OCR 模型** —— 模型惰性加载是秒级的，算进第一帧会让本判据必挂

此测试约 6.5s，标记为慢测。

**Task 3 实际执行结果**（2026-08-06，`tests/test_anchor_offline.py` 跑在 `dataset/images/train` 前 40 帧）：干净锚点命中 22/40（满足 A）；命中帧锚点 y ∈ [738, 888.5]（满足 B，⊂ [700, 950]）；框宽 122-130px（满足 C，< 160px）；单帧中央区扫描**中位 85.9ms、最大 161ms**（满足 D，≤ 400ms）。

注意：本次实测比 §3.1 记录的历史基线（中位 118ms、最大 235ms）更快，两组数据都保留并列记录，**不用新数覆盖旧数** —— 差异未定位根因（推测与运行时机器状态、缓存等有关），判据阈值 400ms 按更保守的历史基线定的，两组数据都远低于阈值，不影响判定。

### 7.3 实弹验证（需管理员提权 + 游戏前台，2560×1440）

- **E**：站桩且攻击区内无怪，60s 内攻击键发送次数 = 0（读日志计数，不靠肉眼）
- **F**：怪进入攻击区后 3s 内发出攻击键
- **G**：标定图上锚点框套住角色本人（不是宠物、不是他人）
- **H**：开启检测模式后 10 分钟挂机，喝药行为与定频模式无差异（验证 §4.6 的阻塞没拖慢保命）

E/F/G/H 未通过前，不得声称功能可用。

## 8. 明确不做

- 角色朝向识别（已确认左右对称即可）
- 无怪时自动找怪（走位/换屏/换频道）—— 用户明确只要停手
- 无怪超时停任务 —— 同上
- YOLO 增加 player 类别
- 精英怪优先级、多技能轮换
