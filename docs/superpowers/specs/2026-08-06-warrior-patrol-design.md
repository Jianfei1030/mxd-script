## 1. 问题

现有方案（mxd）是**法师站桩**：玩家不动，靠远程攻击 + 攻击区等怪走进来。但用户角色是**战士**：

- 攻击距离近，必须**主动接近**怪物
- 被怪碰到会**被打退**，怪被打也会**被打退**——位置持续漂移
- 需要**左右游荡巡逻**打怪，怪进入真实攻击范围才攻击
- 本期**仅考虑纯平地面**（无平台/梯子/跳崖）
- **关键**：战士攻击**有朝向**——只能攻击面对的方向。攻击区不是左右对称，而是**往玩家面朝的一侧绘制**。横版卷轴只有左右 2 个方向

结论：不能照搬「固定屏幕攻击区 + 站桩」，必须补 mxd 缺失的三块能力——**玩家定位**、**巡逻移动**、**朝向检测**。前两者是 MapleStoryAutoLevelUp 的强项；朝向是战士特有、两边都没有现成方案，Phase 1 先用手动/移动推断占位，验证攻击区绘制逻辑，Phase 2 再上自动视觉检测。

## 3. Phase 1：Debug 可视化层（本期实现）

### 3.1 显示机制（复用 ok 框架，零新 UI）

```
任务内:overlay = self.get_overlay_view()          # BaseTask 已有
       overlay.draw('warrior_debug', callback)     # 注册常驻 painter(duration=None)
       callback(QPainter, OverlayWindow):
           ratio = view.frame_ratio()              # 帧像素 → 窗口像素
           painter.drawRect(x*ratio, y*ratio, w*ratio, h*ratio)
```

- `paint_custom`（`OverlayWidget.py:203-211`）每帧遍历 `custom_painters` 调用 callback，任务停止时 `overlay.clear_draw('warrior_debug')`
- 常驻（duration=None）→ 不闪烁；`_boxes_enabled` 开关在 StartTab「Enable Boxes」已存在
- **Phase 1 只读：不调用 send_key，不触发攻击**——纯可视化验证

### 3.2 三个框 + 变色（每 0.3s 刷新一组）

| 框 | 来源 | 绘制 |
|---|---|---|
| 玩家 bbox | 名字牌 OCR 锚点 → 身体中心 → 标定宽高矩形（`玩家宽(像素)`/`玩家高(像素)`，待标定） | 绿色实线 |
| 攻击范围 bbox | 身体中心为锚，**往朝向侧**偏移（见 3.3） | 蓝色实线（无敌） / **红色实线（有怪进入，变色）** |
| 怪物 bbox | YOLO `find_mobs` | 黄色实线 + 脚底点（判定锚点） |

刷新节拍 `调试刷新间隔(秒)` 默认 0.3s，不占 10Hz 保命循环（Phase 1 无保命压力，但仍保持节流习惯）。

### 3.3 朝向 + 攻击范围（核心新概念）

```
朝向: facing ∈ {LEFT, RIGHT}   # 横版只有 2 个方向
玩家身体中心 = 锚点 上移 名字牌到身体偏移(像素)
攻击范围(朝向 LEFT):
    x ∈ [身体中心.x - 攻击距离, 身体中心.x]
    y ∈ [身体中心.y - 攻击区高/2, 身体中心.y + 攻击区高/2]
攻击范围(朝向 RIGHT):
    x ∈ [身体中心.x, 身体中心.x + 攻击距离]
    y ∈ [身体中心.y - 攻击区高/2, 身体中心.y + 攻击区高/2]
```

- **攻击区只画朝向侧**（半矩形），不是左右对称全矩形
- 变色判定：怪物**脚底**（`mob.x + mob.width/2, mob.y + mob.height`）落入攻击范围矩形 → 攻击区框变红（表示「此朝向可命中」）；无怪 → 蓝
- 朝向来源（Phase 1 占位，优先级从高到低）：
  1. **手动切换**：GUI 下拉 `朝向`（`左`/`右`/`自动`）——默认 `自动`
  2. **移动推断**：`自动` 模式下，最近一次方向键动作的方向（Phase 2 巡逻自带；Phase 1 可先用调试快捷键模拟）
  3. **视觉检测**（Phase 2 实现）：角色 sprite 左右朝向模板匹配 / YOLO 加朝向类别，本期不做
- `自动` 且无任何方向历史 → 默认 RIGHT，记 warning

### 3.6 攻击距离标定闭环（玩家输入 → bbox 确认）

攻击距离**没有普适默认值**——战士武器不同，距离长短不一。标定工具做成交互闭环：

```
① 玩家输入 攻击距离(像素) 初值(默认 120)
② 工具抓一帧 → 锚点识别 → 按朝向画 攻击框(box 边界即攻击距离) 存 PNG
③ 玩家看图:攻击框是否贴合当前武器的实际攻击范围?
      贴合 → 确认,写入配置,标定完成
      不贴合 → 改距离重新生成(±20px 步进),回到 ②
```

- 判定参考：站在怪面前实际挥一刀，看**刀刃最远命中点**与攻击框外边界是否对齐
- 攻击框颜色沿用 Phase 1 语义（蓝=无敌，红=有怪进入）——标定时可顺便确认变色
- 标定结果写入 `攻击距离(像素)` 配置，运行时 `WarriorDebugTask`/`MapleFarmTask` 直接读取，无需改代码
- GUI 提供一个「标定」按钮直接拉起此工具（M4 GUI 打磨待办，Phase 1 先命令行）

## 4. Phase 2：巡逻闭环（后续实现，本 spec 原设计）

### 4.1 状态机（借鉴 MSALU FSM，砍到两态）

```
PATROL(巡逻) ──攻击区内检测到怪──→ HUNTING(停走,面向攻击)
   ↑                                    │
   └──────怪死/消失/超范围──────────────┘
```

- **PATROL**：按当前方向走，每节拍检测近战攻击区；区内有怪 → 切 HUNTING
- **HUNTING**：停走，面向怪攻击；怪死/消失 → 回 PATROL（继续原方向）；怪被打退超范围 → 朝怪方向走 0.3s → 回 PATROL

### 4.2 玩家定位（复用锚点，改游走刷新）

复用 Phase 1 锚点机制，唯一改动：站桩版锚点保鲜 10s + 回退屏幕中心；游走版**每个攻击节拍刷新**，快通道小窗跟随（±240×±80），失败慢通道（中央区扫描，`锚点刷新间隔(秒)` 节流），都失败用**上一可信位置 + 巡逻方向外推**，年龄 > `锚点保鲜(秒)` 才回退屏幕中心。

### 4.3 巡逻方向（借鉴 MSALU PatrolState，单屏折返）

```
玩家屏幕 x 比例 = 锚点.x / 帧宽
比例 < 左边界(0.2)  → 向右走
比例 > 右边界(0.8)  → 向左走
否则              → 保持当前方向
```

- `send_key_down(左移键/右移键)` 持续按住走路，切换方向先 up 旧键再 down 新键
- 每节拍重新读锚点判方向（打退后立即纠正，不依赖历史）
- 纯平地无掉落风险，不需要 MSALU 的 is_near_edge/teleport/jump

### 4.4 近战攻击 + 朝向（Phase 1 朝向机制直接复用）

- 攻击范围 = Phase 1 §3.3 的朝向矩形（不再左右对称）
- 攻击触发：怪脚底落入攻击区 → `send_key(攻击键)`；`facing` 与怪所在侧不一致时，先按方向键转向（移动推断更新 facing）再攻击
- 打退处理：靠每帧重定位覆盖（Phase 1 §3.3 已论证）
