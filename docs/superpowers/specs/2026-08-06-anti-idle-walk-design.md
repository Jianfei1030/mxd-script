# 防挂机走位

日期：2026-08-06
状态：设计已确认，待实现
上游：`2026-08-05-ok-mxd-design.md`（MVP 设计）；与 `2026-08-06-attack-zone-mob-gating-design.md`（攻击区怪物门控）相互独立，不依赖其实现分支

## 1. 问题

站桩挂机长时间原地不动，容易被游戏的防挂机判定踢下线，也更容易被反外挂系统识别为固定行为模式的脚本。需要一个定时的小幅走位，让角色看起来像有人在操作。

## 2. 设计

### 2.1 触发节奏

固定间隔 `走位间隔(秒)`（默认 120），到点即检查是否可以走位。判断"到点"直接复用既有的 `farm_logic.should_attack(now, last, interval)`（纯粹是"距上次过去了多久"的判断，语义与新增一个同构函数重复，不新增 `should_walk`，YAGNI）。

### 2.2 与战斗的冲突处理

- **检测模式**：到点时如果这一拍检测判定「有怪在攻击区内」（即将/正在攻击），顺延，不打断输出；等下一次检测判定「无怪」时再走
- **定频模式**：没有「有没有怪」这个概念，到点直接走

检测模式下「这一拍有没有怪」的判断结果，缓存进新状态 `_last_mob_present`（bool，初始 `None`）。走位分支直接读这个缓存，**不为了走位额外触发一次 OCR/YOLO**。启动后还没跑过一次检测时（`_last_mob_present is None`）视为「还不能走」，不会在没有新鲜判断的情况下贸然移动。

### 2.3 走位动作

随机选一侧（左或右），按住方向键 `走位持续时间(秒)`（默认 0.4s）后松开，再按住反方向同样时长后松开。净位移 0：不会走出当前站桩点、不会掉下平台边缘、不会撞进相邻怪群。

用 `self.send_key(key, down_time=hold)` 同步实现（框架既有接口，`down_time` 参数本身就会阻塞按住指定时长），两次调用共阻塞约 `2 * 走位持续时间(秒)`（默认 0.8s）。这个阻塞时长远小于既有的回城卷 `after_sleep=2` 阻塞，接受。

方向选择用 `random.choice`，测试里通过 `patch('random.choice', ...)` 固定下来做确定性断言（该项目里这是第一处需要注入随机性的地方，沿用既有的 `patch('time.time', ...)` 做法）。

### 2.4 配置变更

`config.py` 的 `游戏按键` 全局配置新增两项：

| 键 | 默认 | 说明 |
|---|---|---|
| `左移键` | `left` | 冒险岛默认走位键即方向键，一般不需要改 |
| `右移键` | `right` | 同上 |

`MapleFarmTask.DEFAULT_CONFIG` 新增三项：

| 键 | 默认 | 说明 |
|---|---|---|
| `走位开关` | `True` | 用户明确要防挂机判定，默认开启，不用额外去 GUI 里勾选 |
| `走位间隔(秒)` | 120 | 到点检查一次能不能走（见 2.2） |
| `走位持续时间(秒)` | 0.4 | 单侧按键时长，往返共约 2 倍 |

### 2.5 新增状态（必须进 `_reset_state()`）

- `_last_walk`：上次走位时间，初始 `0.0`
- `_last_mob_present`：最近一次检测判断结果，初始 `None`（未知，见 2.2）

这个项目有过教训：新状态漏进 `_reset_state()` 会导致重新启用任务后计时器不复位、秒发。两个新状态都要在内。

### 2.6 主循环接线

`run()` 里新增独立的第 4.5 步（在攻击步骤之后、拾取步骤之前），不嵌进定频/检测的 `if/elif` 分支内部——走位有自己的 120s 节奏，不能被绑在 1.5s 的攻击节拍上：

```
if cfg['走位开关'] and farm_logic.should_attack(now, self._last_walk, cfg['走位间隔(秒)']):
    can_walk = cfg['攻击模式'] == '定频' or self._last_mob_present is False
    if can_walk:
        self._do_walk(keys)
        self._last_walk = now
```

检测模式的攻击分支里，`mob_in_zone` 判断结果要在跑完检测的那一拍写入 `self._last_mob_present`（无论这一拍最终有没有发攻击键）。

| 文件 | 动作 | 职责 |

## 4. 验证计划

### 4.1 离线单测（`tests/test_farm_task_offline.py`）

- `走位开关` 关闭 → 到点也不走，`send_key` 不含方向键
- 定频模式 + 到点 → 直接走，发两次方向键（顺序由打桩的 `random.choice` 决定）
- 检测模式 + 到点 + 本拍判定有怪 → 不走，顺延
- 检测模式 + 到点 + 本拍判定无怪（`_last_mob_present=False`）→ 走
- 走完后 `_last_walk` 更新为当前时间，短时间内（未到间隔）不会重复走
- 启动后 `_last_mob_present` 仍是初始值 `None`（还没跑过一次检测）→ 即使检测模式下到了走位时间点，也不走

### 4.2 实弹验证（需要人操作，agent 做不了）

- 开着走位挂机一段时间，肉眼确认角色确实会定时小幅左右移动、移动后位置不变（净位移 0）
- 有怪持续进出攻击区时走位不会打断正常输出（顺延生效）

## 5. 明确不做

- 不做多方向/大范围走位（找怪、换平台）——纯粹是防挂机判定，不是找怪机制
- 不做随机化间隔（固定间隔，用户已确认够用）
- 不检测平台边缘——净位移 0 的往返设计本身就规避了这个问题，不需要额外的地形感知
