# 有向攻击区 —— 「能不能打到」与「要不要转向」分开判

日期：2026-08-07
状态：设计已确认，待实现
上游：`2026-08-06-attack-zone-mob-gating-design.md`（攻击区与锚点，§4.4 定的左右对称）、`2026-08-06-warrior-patrol-design.md`（§3.3 已提出朝向矩形）

## 1. 问题

`_do_attack`（`MapleFarmTask.py:544-559`）只看 `_last_mob_present`，**不检查怪在不在面朝侧**。而 `_last_mob_present` 来自左右对称的攻击区（`:416` `farm_logic.attack_zone`）。

于是存在一条**与朝向信念完全无关、代码级可证**的挥空路径：

```
面朝右，唯一的怪在左边 200px（落在对称区内）
  ↓
raw_present = mob_in_zone(centres, 对称zone) = True        :428
  ↓
attack_turn_direction(...) 返回 'left'                      :451
  ↓
被 turn_allowed(转向冷却 1.5s) 挡住 → 没转成                :453
  ↓
_do_attack 只看 _last_mob_present（仍是 True）→ 按攻击键     :557
  ↓
面朝右，打左边的怪 = 挥空
```

用户配置里 `转向冷却(秒)=1.5`、`攻击间隔(秒)=0.7`，冷却比攻击节拍长一倍，这个窗口一点都不罕见。

**用户技能已确认是魔法箭类（面朝向直线单体）**，对称攻击区从建模上就是错的。

## 2. 根因：一个区在同时干两件事

```
attack_turn_direction(facing, body_x, centres, zone)   ← 决定「要不要转向」
mob_in_zone(centres, zone) → mob_present → _do_attack  ← 决定「能不能打」
                       ↑ 同一个 zone
```

对有向技能，这两件事的正确区域不同：

- **要不要转向**：必须看左右两侧——不看背后就不知道有没有值得转过去的怪
- **能不能打**：只有面朝侧的怪打得到

历史成因：attack-zone spec §4.4 写死「左右对称（不做朝向，已确认）」、§8 明确「不做角色朝向识别」——那是**还没有朝向概念时**的简化。后来 `b23f0e0 feat: warrior auto-facing` 把朝向加了进来，**攻击区从没跟着改**。

| 去抖 `mob_present_debounced` | `farm_logic.py:64`，`丢怪保持(秒)` 默认 1.0 |

### 3.1 历史实测（前序会话，直接引用，本次未重测）

- 攻击区尺寸扫描（118 帧逐帧几何）：`800x200` → 平均区内怪 0.36 / 有怪帧 28% / **两侧都有仅 6%**
- 同层怪框中心全落在锚点 `-105..-2`，现行 高=200（覆盖 `-188..+12`）对同层怪覆盖率**已是 100%**，误收邻近平台仅 5%
- 645 只检测里只有 23% 是同层，同层怪水平距离**中位 616px**
- 攻击区宽 800→1007 让转向更糟：转向频率 0.090→0.126 次/秒
- 每拍重选最近怪 → 换边率 38%；转向冷却 1.5s、侧占用去抖 **均已验证无效**

### 3.2 待验证假设（不许当结论用）

- **魔法箭的真实射程未标定**。现行「半宽」（1007/2 ≈ 503px）是从对称宽推出来的，从来没有验证过等于技能射程。§7.3 判据 B 就是用来暴露这一点的。
- 「攻击次数下降但经验不下降」是本设计的预期，不是已知事实。

## 4. 设计

一句话：**保留对称区当「接敌区」（管转向/寻怪，一个字不改），新增一个「攻击区」= 接敌区的面朝侧一半（只管按不按攻击键）。**

### 4.1 两个区，两个信号

| | 接敌区 | 攻击区 |
|---|---|---|
| 形状 | 对称，`攻击区宽 × 攻击区高`（=今天的 zone） | 单体模式：接敌区的**面朝侧一半**；群体模式：= 接敌区 |
| 信号 | `_last_mob_present`（**保持现名现义**） | `_last_attack_present`（新增） |
| 消费者 | 转向/寻怪分支、坐椅 `:529`、忙判定 `:753`、走位 `:765` | **只有** `_do_attack` `:557` |

**关键：不是把 `_last_mob_present` 换成有向的，而是新增一个信号。** 坐椅/走位/忙判定问的是「附近有没有怪」，那是接敌区的语义；只有攻击问的是「打不打得到」。混为一谈会把三个不相干的行为一起改坏。

### 4.2 行为矩阵

| 情形 | 接敌区 | 攻击区 | 行为 |
|---|---|---|---|
| 怪在面朝侧 | 有 | 有 | 打 ✓ |
| 怪在背侧 | 有 | **无** | 原地转向（不寻怪），下一拍就打 ✓ |
| 怪在背侧 + 转向被冷却挡住 | 有 | **无** | **不打** ✓ ← §1 的 bug 在此消失 |
| 两侧都没有 | 无 | 无 | 寻怪 ✓ |

第二行同样重要：背后的怪仍然**原地转身打**，不会退化成「寻怪走过去」——因为转向/寻怪的分支判据仍然是接敌区。

`attack_turn_direction` **一个字不改**，继续吃接敌区。所以 §3.1 里那些已验证失败的方案（目标侧锁定改动、转向冷却、侧占用去抖）一个都不会重踩。

### 4.3 朝向未知时的回退

`_facing is None`（首次启动，或上游 `cf4ee6f` 受击后作废）时，攻击区**回退为整个接敌区**（= 今天的行为）。

理由：不制造新的挂死风险。若改成「朝向未知就不打」，一旦转向键长期送不出去（窗口失焦），`_facing` 会一直是 None，角色就永远不攻击。回退到对称区最坏也只是保持今天的表现。

暴露面有限：`attack_turn_direction(None, ...)` 会立刻按最近怪定向并轻点，`_facing` 在**下一拍**就有值，所以每次受击最多一拍走对称区。

### 4.4 判定点与 y 方向：一律不动

- 判定仍用**框中心** `mob_in_zone`，不换成 `warrior_attack_zone` 配套的脚底判定
- `攻击区高` 与 y 范围不动

理由：§3.1 的「同层怪覆盖率 100%、误收 5%」是按**框中心**标定出来的；换成脚底判定会让整套 y 标定失效，得重标。**一次只改一个变量**，本次只改 x 方向的对称→有向。

### 4.5 不新增射程参数

单体模式的面朝侧射程 = `攻击区宽(像素) / 2`。

真实射程从来没标定过（§3.2），现在加一个独立 `单体射程(像素)` 只是把未知包装得更精致，还多一个要维护的旋钮。等 `scripts/calibrate_attack_zone.py` 标出真值、确认射程 ≠ 半宽，再拆参数。

### 4.6 边界约定

面朝右时攻击区 = `[body_x, body_x + 宽/2]`，面朝左 = `[body_x - 宽/2, body_x]`，两端都闭。正压在身上的怪（`x == body_x`）两个朝向都算命中——这种怪的左右判定纯是噪声，与 `farm_logic._on_side` 的既有约定一致。

### 4.7 配置变更

| 键 | 默认 | 说明 |
|---|---|---|
| `攻击区形状` | `单体(面朝)` | `单体(面朝)`：只打面朝侧半区（魔法箭/近战等有向技能）。`群体(对称)`：打整个攻击区，行为等同改动前。注册 `config_type` 下拉 |

`攻击区宽(像素)` 语义不变（接敌区总宽，也是群体模式的攻击区宽）。**群体模式必须逐键等同于改动前行为**——这是安全退路。

### 4.8 可观测性

决策日志（`决策日志开关`，默认关）那一行加两个字段：

```
… 区内=N(左a/右b) 可打区内=M 可打=True/False …
```

`可打区内` = 攻击区内怪数，`可打` = 去抖后的 `_last_attack_present`。单体模式下 `可打区内 ≤ 区内` 必须恒成立，这是判据 A 的数据源。

调试 overlay（`启用标记框`）画**两个框**：接敌区用细线暗色，攻击区用粗线亮色。这也是 §7.3 判据 D 的视觉验收对象。

## 5. 代码结构

| 文件 | 动作 | 内容 |
|---|---|---|
| `src/task/farm_logic.py` | 修改 | 新增纯函数 `facing_half_zone(zone, body_x, facing)`：facing 为 `'LEFT'`/`'RIGHT'` → 返回对应半区；其余（`None`/异常值）→ 原样返回 zone |
| `src/task/MapleFarmTask.py` | 修改 | `DEFAULT_CONFIG` 加 `攻击区形状` + `config_type` 下拉 + 说明文案；`_reset_state()` 加 `_last_attack_present`、`_last_attack_seen`；`_detect_and_act` 算攻击区与第二路去抖；`_do_attack` 改读 `_last_attack_present`；`_draw_debug` 画两个框；`_log_decision` 加两字段 |
| `tests/test_farm_logic.py` | 修改 | `facing_half_zone` 单测 |
| `tests/test_farm_task_offline.py` | 修改 | 接线用例（见 §7.2） |

`facing_half_zone` 接收**已算好的对称 zone**而不是 `(center, width, height)`：调用方本来就有 zone，传它进去可以保证两个区严格同源、y 范围一定一致，不会因为两处各算一次而漂移。

**热重载注意**：改了 `farm_logic.py` 必须重启 GUI（`ok/gui/tasks/TaskManger.py` 的 `importlib.reload` 不递归依赖）。

### 5.1 `_detect_and_act` 的插入点

在 `:416` 算完 `zone` 之后、`:428` 之前插入攻击区计算；攻击区**用本拍转向之前的 `self._facing`**。注意插入点在 `:438` 之前，`facing_before` 这个局部变量此时还不存在——直接读 `self._facing` 即可，此刻本拍尚未转向，二者同值。

这意味着「转向后要等下一拍才攻击」——**这是有意的**。用转向后的新 `_facing` 立刻判定，等于又一次相信「我按了键所以已经转过去了」这个盲写信念，而那正是这一系列 bug 的来源。用户配置 `攻击间隔=0.7`，一拍的代价可接受。

## 6. 预期副作用（必须提前接受）

「能打」的拍数大约**减半**，攻击键触发次数明显下降，体感像是"变得不怎么攻击了"。

但下降的那一半**本来就打不中**（空放 MP）。所以正确的判据是 **攻击次数下降、每分钟经验不下降**（§7.3 判据 B）。若经验也跟着掉，说明射程估计错了（半宽 < 魔法箭真实射程），需先标定再调大 `攻击区宽(像素)`。

## 7. 验证计划（判据事先写死）

### 7.1 纯函数单测（`tests/test_farm_logic.py`）

`facing_half_zone(zone, body_x, facing)`，输入 zone = `(880, 530, 1680, 730)`、body_x = 1280：
- `'RIGHT'` → `(1280, 530, 1680, 730)`
- `'LEFT'` → `(880, 530, 1280, 730)`
- `None` → 原样返回 `(880, 530, 1680, 730)`
- 非法值（`'UP'`、`''`）→ 原样返回（不抛）
- y 范围在所有分支下与输入完全一致
- body_x 落在 zone 外（外推/回退导致）→ 不抛异常，返回的矩形允许退化为空（`x0 >= x1`），由 `point_in_zone` 天然判否

### 7.2 任务级离线测试（`tests/test_farm_task_offline.py`）

几何前提照既有约定：`DEFAULT_CONFIG['角色名']` 为空串 → 锚点回退画面中心 **(1280, 720)**、身体 (1280, 630)、接敌区 x∈[980,1580] y∈[530,730]（按默认宽 600）。

- 单体 + 面朝右 + 怪在右 → 发攻击键
- **单体 + 面朝右 + 怪只在左 + 转向冷却未过 → 不发攻击键**（§1 的 bug，本条是核心回归）
- 单体 + 面朝右 + 怪只在左 + 冷却已过 → 发转向键、**本拍仍不发攻击键**，下一拍（`_facing` 已是 LEFT）才发
- 单体 + `_facing is None` + 怪在左 → 发攻击键（§4.3 回退）
- **群体模式 → 与改动前逐键一致**（同一场景下 `send_key` 调用序列相同）
- 怪在背侧时 `_seek_dir` 仍为 `None`（走转向分支而非寻怪分支）
- **坐椅/走位/忙判定仍由 `_last_mob_present` 驱动**：怪在背侧（接敌区有、攻击区无）时不坐椅、不走位
- 去抖独立：攻击区漏检一拍，`丢怪保持` 内 `_last_attack_present` 仍为 True
- 决策日志含 `可打区内` 与 `可打`，且单体模式下 `可打区内 ≤ 区内`

跑测试前必须确认 `screenshots/test_frames/` 是目录且含 `training_ground_full_2560x1440.png`（每次跑 GUI 都会被清掉，备份在 `_frames_backup/`）。

### 7.3 E2E + 实弹（AGENTS.md §11.3 要求）

**D（E2E 截图视觉验收，合入门槛）**：启 `main_debug.py` → 开 `启用标记框` + 检测模式 → 截图（`scripts/_e2e_capture.py <pid> <out>`）→ 存 `screenshots/e2e/directional_attack_zone/`。
视觉模型必须能确认：画面上有**两个矩形**，粗亮框只覆盖角色的**一侧**，且该侧与角色面朝方向一致。验收 FAIL 不许合入。

**A（几何自洽 + 功能确实生效）**：开 `决策日志开关` 挂机 10 分钟，`可打区内 > 区内` 的行数必须为 **0**；且 `可打=True` 的拍数 / `有怪=True` 的拍数 落在 **0.3–0.8**。
比值 = 1.0 → 有向区没生效（或形状配成了群体），A 不过则 B/C 无意义。

**B（不变差）**：同一地图、同一时段，`攻击区形状` 单体/群体**交替各跑 3 轮 × 10 分钟**，记每轮每分钟经验增长。
通过线：**单体组中位数 ≥ 群体组中位数 × 0.9**。
低于 0.9 → 射程估计错（半宽 < 真实射程），先用 `scripts/calibrate_attack_zone.py` 标定再调 `攻击区宽(像素)` 重测，不许直接回滚了事。
（0.9 是事先约定的通过线，不是效果预测。经验噪声大，交替 3 轮取中位是为了压掉刷新率波动。）

**C（症状消失）**：同一批日志里，`受击` 之后 3 秒内的拍，`可打=True` 的占比应低于全局 `可打=True` 占比——即受击后确实进入了「不乱打、先转向」的状态。并由用户主观确认不再出现"背对怪挥空"。

A/B/C/D 未全部通过前，不得声称此 bug 已修复。

## 8. 明确不做

- **换成脚底判定 / 改 y 范围** —— §4.4，一次只改一个变量
- **新增独立射程参数** —— §4.5，等标定
- **改 `attack_turn_direction` / `seek_direction` / 转向冷却** —— §3.1 已证明动选边规则的方案会引入交替
- **朝向模板匹配** —— 已实测可行，留档在 `2026-08-07-facing-reassert-on-hit-design.md` 附录 A，本次不做
- **`2026-08-07-facing-reassert-on-hit-design.md` 里的「受击后重申朝向」** —— 该 spec 已被上游 `cf4ee6f`（受击 → `_facing=None` + 重置转向冷却）覆盖，且本设计把「没转也照打」这一步堵死后，朝向信念错的后果从"空放技能"降级为"不打 → 转向/寻怪"（两条路径都会重按方向键，本身自愈）。**该 spec 待 §7.3 数据出来后重估或撤销**，不在本次实施范围
