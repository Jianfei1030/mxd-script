关键事实（已核实）：
- 玩家在小地图上的标记 = **黄色点**（用户确认）；M0 实测（2026-08-05）：红点=其他玩家/装饰，黄点=NPC/玩家，青圈=传送门，**小地图不画怪**
- 底图资产已有：`minimap/东部岩山5.png`，122×94、透明背景（A=0）、纯地形层，风格与游戏内小地图渲染一致
- 游戏内小地图面板：位置固定左上角，有 -/+ 缩放与折叠；整图可完整显示于面板内（训练场截图确认）→ **每帧免模板匹配**，标定一次后线性变换即可
- 移动键在怀旧服默认：方向键 + Alt（跳）；按"上"靠近传送门会误进图（守护必须覆盖）

## 1. 总体架构

```
minimap/<地图名>/                     ← 资产目录（通用机制，首发=东部岩山5）
  ├─ 底图.png                         ← 122×94 透明地形层（已有：东部岩山5.png）
  ├─ route1.png / route2.png ...      ← 录制器产出，与底图同尺寸透明层
  └─ map_meta.json                    ← 标定：面板地图区 ROI / scale / offset / search_range 覆盖

src/detect/minimap.py (新)            ← 感知：面板裁剪、黄点质心、坐标变换、多点跟踪（纯函数）
src/task/route_logic.py (新)          ← 决策纯函数：路线加载、最近色搜索、状态机转移
src/task/MapleFarmTask.py (改)        ← 加「移动模式：站桩/路线巡逻」+「巡逻地图」+ 移动键配置
scripts/route_recorder.py (新)        ← 录制工具（WGC 抓帧 + 键盘监听 + 着色 + 分段保存）
tests/test_route_logic.py / test_minimap.py / test_minimap_offline.py (新)
```

**每拍数据流**（巡逻模式，复用 MapleFarmTask 现有 run() 节拍）：

```
帧 → 面板裁剪 → 黄点质心 → 地图坐标 → 最近路线色(search_range)
   → 状态机(FOLLOW/COMBAT/CLIMB/RECOVER) → 方向键/上/跳
   ↑ 现有保命/喝药/攻击区/朝向/守护逻辑原样照跑
```

**移动权仲裁**：
- 巡逻只在**空闲**时驱动移动（攻击区无怪、无硬直）
- 怪进攻击区 → COMBAT：方向键全松，现有攻击/朝向逻辑接管；区清（复用现有丢怪保持配置判定）→ 回 FOLLOW
- 巡逻模式下「寻怪开关」**强制忽略**（用户定：不主动追怪），「防挂机走位」自动停用（巡逻本身就是移动）

决策全部放 `route_logic.py` / `minimap.py` 纯函数（§11.2 铁律），run() 只做 IO。

## 2. 感知层（小地图 → 地图坐标）

### 2.1 标定（一次性，随资产入库）

录制器首跑时标定：抓一帧 → 以底图 alpha 为 mask `matchTemplate`，把底图地形对准面板地图区 → 算 `scale + offset` 写入 `map_meta.json`。
**校验门槛**：匹配分过低（面板折叠/缩放档不对/被遮挡）→ 报错停任务，不猜。

### 2.2 每帧定位（零模板匹配）

1. 按 `map_meta.json` 的 ROI 裁剪面板地图区
2. HSV 黄色阈值 → 连通域 → **质心（亚像素，0.2~0.5px 级）**
3. 线性变换：`map_xy = (dot_xy − offset) / scale`

### 2.3 多黄点消歧（NPC 也是黄点）

- **初始化 = 移动捕获**（录制器与巡逻启动时都做）：命令角色左/右各走一步，动的黄点 = 自己（M0 实测已确认移动点=玩家）
- **之后跟踪**：每帧取离上一位置最近的黄点
- **丢失**：容忍 2s，超时进 RECOVER（小步走动重新捕获）；>10s 捕不回 → 停任务报警

## 3. 路线数据

**格式**：route png = 与底图同尺寸**透明层**（122×94），alpha>0 像素 = 命令色。地形与路线天然分离，**砍掉 MSALU 的 `mask_route_colors` 撞色处理**（`common.py:743`）。录制器显示时把路线层叠加在底图上。

**颜色命令表**（战士裁剪版，出自 MSALU `config_default.yaml` 的 `route.color_code` + `color_code_up_down`，14 色砍 10 色，去 4 个传送色）：

| 颜色 | RGB | 命令 | 用途 |
|---|---|---|---|
| 红 | 255,0,0 | `left none none` | 向左走 |
| 蓝 | 0,0,255 | `right none none` | 向右走 |
| 橙 | 255,127,0 | `left none jump` | 左跳 |
| 青 | 0,255,255 | `right none jump` | 右跳 |
| 品红 | 255,0,255 | `none none jump` | 原地跳 |
| 石灰 | 127,255,0 | `none down jump` | 跳下台子 |
| 灰 | 127,127,127 | `none up none` | 爬（上） |
| 浅黄 | 255,255,127 | `none down none` | 爬（下） |
| 浅绿 | 0,255,127 | `stop stop stop` | 停（站桩点） |
| 黄 | 255,255,0 | `none none goal` | 段终点 → 切 route N+1 |

**最近色搜索**（出自 MSALU `get_nearest_color_code`，`MapleStoryAutoLevelUp.py:568-619`）：以黄点地图坐标为中心、`search_range` 方框内取曼哈顿距离最近的命令色。两点裁剪：
- **`search_range` 默认 8**（MSALU 固定 10；东部岩山5 层间距 15~25px，10 易串层），`map_meta.json` 可按图覆盖
- **砍掉 MSALU 双色互补**（`:1447-1457`，治梯子卡顿的补丁）——由 CLIMB 验证重试替代

**分段循环**（出自 `check_reach_goal` `:1533-1537` + `idx_routes` 取模 `:1573`）：`goal` → route1 → route2 → … → route1。单程折返图录两段（去/回）。

## 4. 决策状态机（核心）

```
         攻击区有怪              区清(丢怪保持判定)
FOLLOW ────────────► COMBAT ──────────────────► FOLLOW
  │ ▲
  │最近色=up/down        │ goal→切下一段
  ▼ │                   │ 位置60s无位移 / 黄点丢失>2s
CLIMB ───────────────► RECOVER ──恢复────────► FOLLOW
  │ 爬完(最近色变走色)     │ 超时(10s)
  └─────────────────────► 停任务报警 ◄──意外换图/掉线/弹窗(任意态)
```

- **FOLLOW**（≈ MSALU `update_cmd_by_route` `:1441` 的默认行为）：按最近色命令驱动方向键/跳。走色是线沿线走，跳色是点状 blob 压到才跳
- **COMBAT**（我方现有逻辑，零改动）：方向键全松，攻击/朝向接管；区清回 FOLLOW——**最近色机制天然容忍击退位移**，被推飞也能从当前位置找回路线
- **CLIMB（上下层，验收关卡 3 的实现；MSALU 无对应物，全新）**四子阶段：
  1. **对位**：继续朝梯子方向走，直到黄点与**触发 CLIMB 的那个爬色像素**的小地图横向差 |dx| ≤ 1 格
  2. **爬**：按住上/下，**用屏幕锚点 y 验证爬动**（屏幕像素级，比小地图灵敏 ~25 倍；锚点中途丢失时降级用小地图黄点 y 验证）
  3. **重试**：1.5s 无位移 → 朝梯子方向 tap 一小步 → 再按，最多 4 次
  4. **退出**：最近色从爬色变回走色 → FOLLOW；4 次全失败 → RECOVER
- **RECOVER**（改编自 MSALU watchdog `:1523-1531` 的随机乱动，改为定向恢复）：左右小步走重新捕获黄点/找回路线；10s 恢复不了 → 停任务报警
- **全局守护**：任意态检测到意外换图 / 掉线 / 弹窗 → 停任务报警

**新增配置键**：`移动模式`(站桩/路线巡逻，默认站桩) / `巡逻地图` / `移动键左·右·上·下`（默认方向键）/ `跳跃键`（默认 Alt）。
CLIMB 参数（对位阈值 1 格 / 验证窗 1.5s / 重试 4 次）放代码常量，不进 GUI（YAGNI）。

## 5. 录制器（scripts/route_recorder.py）

MSALU `tools/routeRecorder.py` 的 mxd 版，复用 `scripts/capture_frame.py` 的 `build_capture()`（WGC）。

1. **首跑标定**（§2.1）→ 写 `map_meta.json`；匹配分低 → 报错
2. **初始化**：移动捕获锁定自己的黄点（§2.3）
3. **录制循环**（~10Hz）：抓帧 → 黄点质心 → 地图坐标；监听**实际按下的物理键**决定涂色（新增键盘监听依赖 `keyboard`/`pynput` 二选一，仅录制器，计划阶段定）：

| 你按的键 | 涂下 | 形式（出自 MSALU routeRecorder） |
|---|---|---|
| 左/右（走着） | 红/蓝 | **线**：上一位置→当前位置连线 |
| 跳 / 跳+方向 | 品红/橙/青 | **blob**：半径 2 圆点，0.7s 冷却 |
| 上 / 下 | 灰/浅黄 | 爬色 blob |
| F2 | 黄 goal 点 | **保存 routeN.png，开新段** |
| F3 | — | 撤销上一笔（操作栈整层重画） |
| F4 | — | 放弃当前段重录 |
| ESC | — | 退出 |

显示窗口：底图+路线层放大 6 倍 + 当前黄点十字线 + 按键提示。
**两个防呆**：黄点丢失 >0.5s 断线不连（防垃圾长线）；blob 冷却防连涂。
录制完成肉眼对照 = 验收关卡 1；顺带输出**黄点质心抖动统计**（std/95 分位，实测 1 落账）+ 存 20 帧面板裁剪存档帧（离线测试用）。

## 6. 守护细节

现有六重守护（保命/喝药/死亡/弹窗等）原样照跑。巡逻新增四道：

| 守护 | 机制 | 后果 |
|---|---|---|
| **意外换图** | 每 1~2s 校验面板地形与底图匹配分（误入传送门 → 分崩） | 停任务 + 报警 |
| **卡死** | 地图坐标 60s 无位移（验收关卡 2 定义） | RECOVER；10s 恢复不了 → 停任务报警 |
| **黄点丢失** | >2s RECOVER 定向找回；>10s 捕不回 | 停任务报警 |
| **启动校验** | 面板折叠/缩放错/底图对不上 | 报错不开跑 |

**传送门专项**（怀旧服按"上"会进传送门）：
- FOLLOW 走/跳色**都不含 up**，巡逻主循环永远不会在传送门旁按上；唯一按上的是 CLIMB（爬色触发）
- **录制规范**：爬色 blob 必须远离传送门涂（录制窗口里传送门是青圈，可见）
- 双保险 = 意外换图守护：真进了门，1~2s 内停任务

## 8. 里程碑与验收（判据写死）

| 里程碑 | 内容 | 判据 |
|---|---|---|
| **M0 感知地基** | 标定 + 黄点定位 + 变换 + 录制器 | **关卡 1**：手动走一遍录出 route1.png，轨迹肉眼吻合；质心抖动统计落账；20 帧存档帧入库 |
| **M1 单层巡逻** | FOLLOW + COMBAT + goal 轮转 + overlay 状态显示；路线只涂平层走/跳色 | **关卡 2**：≥3 圈无卡死，进区怪被清 |
| **M2 上下层** | CLIMB 四子阶段 | **关卡 3**：走到→对位→爬上→继续走，3/3 成功；梯子容差顺带标定 |
| **M3 守护加固** | RECOVER + 换图/卡死/丢点 | **关卡 4**：手动制造换图、卡死各一次，10s 内停任务报警 |
| **M4 实机验收** | 完整路线长跑 | **关卡 5**：30 分钟无干预、无中断、无漂移 |

顺序依赖：M0 → M1 → M2 → M3 → M4。风险最高的 CLIMB 放单层跑通之后，地基问题不与精度问题搅在一起。
