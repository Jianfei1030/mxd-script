### 2.2 「受击会翻转朝向」被证伪

52 个分歧事件按「距上次受击」分桶：

```
[0.0, 0.5)s :  0
[0.5, 1.0)s :  1
[1.0, 2.0)s :  4
[2.0, 4.0)s : 10
[4.0, 8.0)s : 13
>=8.0s      : 24
```

受击后 0.5 秒内**一次分歧都没有**，分布随「距上次受击」单调上升。若受击会翻朝向，分歧必然扎堆在最前面的桶。

`MapleFarmTask.py:855` 那行 `self._facing = None` 的唯一前提就是「受击可能让朝向失效」。**前提不成立。**

### 2.3 清空信念的代价（用观测器直接反判，非推断）

`facing_half_zone` 在 `facing is None` 时**原样返回整个对称区**。于是清空信念的每一拍，有向攻击区都失效：

| | 拍数 | 占有答案拍 |
|---|---|---|
| 信念错 + 开火（A 类，判据 C 量的就是它） | 19 | 1.30% |
| 信念空 + **面朝侧一只怪都没有**（B 类） | 19 | 1.30% |
| 合计 | 38 | **2.60%** |

B 类是拿**实测朝向**反判出来的：这些拍按对称区判定"可打"、按下了攻击键，而角色实际面朝的那一侧区内一只怪都没有 —— 确定性打空。

A 类与 B 类互斥：判据 C 只统计 `facing_before in (LEFT, RIGHT)` 的拍，受击清空后的那些拍它从来没算过。两者要相加。

### 2.4 本设计不解决的（更大的那个）

同一轮的时间预算：

| | 占比 |
|---|---|
| 可打=True（在输出） | 38.1% |
| 寻怪中（在移动） | 19.0% |
| **发呆（屏幕有怪却既不打也不追）** | **37.9%（756 秒 / 41.8% 时间）** |
| 发呆（屏幕真没怪） | 5.0% |

**比朝向问题大 16 倍。** 但现在定位不了：决策日志只记 `怪=N` 和 `区内=N`，不记怪的几何位置，分不清「地图本身同层怪就少」（memory：645 只检测里只有 23% 同层、同层怪水平距离中位 616px，而攻击区半宽仅 503px）与「同层判定过严」。

**这条不在本设计范围内**，需要先加几何日志再单独开一条。混进来会重蹈 2026-08-07 那四轮「改完不知道是哪条起作用」的覆辙。

## 3. 设计

### 3.1 改动一：受击不再清空信念

`MapleFarmTask.py:855` 删掉 `self._facing = None`。

`self._last_turn = 0.0`（转向冷却重置）**保留不动**：它的原注释理由（"翻了你补 tap 是纠错；没翻，朝怪 tap 50ms 是 no-op"）在"没翻"这一支下仍然成立，且代价只是一次零成本的同向轻点。删它是独立的行为改动，不在本设计范围（见 §6）。

受击日志行的 `朝向=X→- 信念作废` 措辞要跟着改，否则日志会说谎。

### 3.2 改动二：观测器升级成纠正器

在 `_detect_and_act` 里，观测之后、`attack_area` 计算**之前**：

```
observed, obs_s, obs_flip = self._observe_facing(frame, anchor_hit, source)
belief_before_obs = self._facing          # 判据 C 的尺子,必须在纠正前存下来
if 朝向纠正开关 and observed is not None and observed != self._facing:
    self._facing = observed
```

位置是关键：纠正必须发生在 `facing_half_zone` 取用 `self._facing` 之前，否则本拍的攻击区仍按错朝向算，白纠正一拍。

规则：

| 情况 | 行为 |
|---|---|
| 观测给出答案且与信念不符 | **以观测为准写回** |
| 观测给出答案且与信念一致 | 无操作 |
| 观测弃权 | 信念不动 |
| 锚点非真命中（cached/fallback） | 不观测，信念不动 |
| 还没采到模板 | 不观测，信念不动（= 改动前行为） |

### 3.3 这一改顺带解决的三件事

1. **A 类危害**：信念错一两拍内被观测纠回（可用率 77%，弃权不会给错答案）。
2. **§2 死锁**：清空信念原本顺带提供了一个副作用 —— 打破「信念错 + 目标侧锁定 → `attack_turn_direction` 永远返回 None → 永不转向」。删掉清空会把死锁放回来，**观测纠正正是它的正解**：不再靠"把信念抹掉"这种手段，而是直接把信念修对。
3. **吞键那 3%**：转向 tap 被施法吞掉、`_facing` 却盲写翻转的那些拍，下一次观测就纠回来了。**动画忙窗要解决的问题，观测纠正顺手解决，且不需要推算任何动画时长、不是开环模型。**

### 3.4 保住尺子：纠正不能让判据 C 失明

一旦开始纠正，`facing_before` 就等于纠正后的值，`朝向分歧` 行永远不会再触发 —— **修复会把测量它的仪器弄瞎**，之后没人知道分叉率是真降了还是只是看不见了。

所以分歧行必须用**纠正前**的信念来判：`divergence_log_line(belief_before_obs, observed, ...)`。字段与格式函数都不动，只是传参改成纠正前的值。

**实现时的偏离（2026-08-08）**：设计原本还要另加一行 `朝向纠正 信念=… → 实测=…` 和一个 `correction_log_line` 格式函数，**没有实现，也不需要**——分歧行既然已经改用纠正前的信念判定，纠正发生时它必然触发，两者一一对应。`grep 朝向分歧` 数出来的就是纠正次数，判据 E2/E4 照样有数据源。多写一行只是同一事件的第二份记录。

### 3.5 配置

| 键 | 默认 | 说明 |
|---|---|---|
| `朝向纠正开关` | `true` | 观测到真实朝向与信念不符时，以观测为准。关掉 = 观测器退回只读 |

开关语义要理顺（观测的**计算**与观测的**日志**是两回事）：

- 观测计算在「`朝向纠正开关` 或 `朝向观测开关`」任一为真时执行
- `朝向观测开关`（默认仍为 `false`）此后只控制**日志详略**（决策行的 `实测=`/`分值=` 字段、分歧行、纠正行）

这样纠正作为常驻功能可用，不必逼用户打开排查级日志；而排查时打开观测开关就能看到全部痕迹。

### 3.6 模板依赖与优雅降级

纠正依赖模板，而模板要等第一次寻怪走动确认（沿按键方向真走够 40px）才采得到。启动后到采到模板之间，纠正完全不生效 —— 行为与改动前一致，不是故障。

换发型/装备会让模板失效，表现为**弃权率上升**而不是给错答案（附录 A：0 误判）。判据 A 就是盯这个的。

## 5. 验证计划（判据事先写死）

### 5.1 离线单测

- 观测有答案且不符 → `_facing` 被写成观测值，且**本拍的 `attack_area` 用的是纠正后的朝向**（断言半区边界，不是断言 `_facing`——后者测不出"纠正得太晚"）
- 观测有答案且一致 → 不写、不记纠正日志
- 观测弃权 → `_facing` 不变
- `source='cached'` → 不观测、`_facing` 不变
- 没模板 → `_facing` 不变
- `朝向纠正开关=false` → `_facing` 不变，**逐键行为与改动前一致**
- 受击 → `_facing` **不再被清空**（守住改动一）
- 分歧行用的是**纠正前**信念（守住 §3.4 的尺子；变异验证：把传参改成纠正后的值，此用例必须红）

### 5.2 实弹判据（同一地图，≥20 分钟，开 `决策日志开关` + `朝向观测开关`）

**E1（B 类危害归零）**：受击之后的拍里，`朝向=-` 且 `可打=True` 的拍数 **= 0**。
构造上保证（不再清空），本条是回归守卫。

**E2（A 类危害下降）**：「信念错且开火」占有答案拍 **≤0.3%**（对照基线 1.30%）。
不设 0：观测有 23% 的拍不可用（锚点非真命中）+ 弃权，纠正必然有延迟。

**E3（不引入左右交替）**：转向频率 **≤ 对照组的 1.2 倍**。
2026-08-07 有四个动过朝向的方案引入了交替，这条是防止我判断错了。

**E4（纠正不是新噪声源）**：纠正事件中，被**下一次**观测立刻反向纠回的比例 **≤5%**。
防止观测在两个值之间抖动，把角色抖成左右扭。B=0.4% 说明不该发生，这条是兜底。

**E1–E4 未全部通过前，不得声称此 bug 已修复。**

判据 A/B 照常复算：纠正上线后仪器本身必须仍然可信，否则 E2 的数字没有意义。

## 6. 明确不做

- **删 `_last_turn = 0.0`（受击重置转向冷却）** —— 独立的行为改动。删了会让转向冷却在受击后不再被绕过（受击约 7 次/分，即每分钟 7 次绕过冷却的机会），可能改变交替率。要改就单独一轮、单独量 E3，不和本设计混在一起
- **动画忙窗** —— 判据 D = 0.78 未坐实，按事先写死的决策线不做。观测纠正已经覆盖了它的目标场景（§3.3.3）
- **41.8% 的「有怪却发呆」** —— 更大 16 倍，但需要先加怪的几何日志才能定位，单独开一条（§2.4）
- **改 `facing.py` 的判定逻辑/阈值** —— 判据 A/B 刚验证过它可信，没有理由动
- **把观测接进寻怪/走位的朝向写入** —— 那两条路径每拍重按方向键、本来就自我重申（`2026-08-07-facing-reassert-on-hit-design.md` §3.2），缺口只在站桩攻击
- **换发型自动重采模板** —— 表现为弃权率上升，判据 A 看得见就够
