# 朝向观测器（只读）—— 先造尺子，再动刀

日期：2026-08-08
状态：设计已确认，待实现
上游：`2026-08-07-facing-reassert-on-hit-design.md`（受击后重申朝向，**设计已确认但从未实现**；其附录 A 是本设计的直接来源）、`2026-08-07-directional-attack-zone-design.md`（有向攻击区）

## 1. 为什么是观测器，而不是修

`_facing` 是纯信念：只有「我们自己按了方向键，所以认为角色转过去了」这一种写入方式。项目在这上面已经改了四轮：

| 轮次 | 改动 | 结果 |
|---|---|---|
| 2026-08-07 | 目标侧锁定（`attack_turn_direction`） | 换边率 38% 的老问题解了，但反向翻转 6→6 没降 |
| 2026-08-07 | 转向冷却 1.5s | 反向 12→9，要挡住得设 3.5s+ —— **记为无效** |
| 2026-08-07 | 侧占用去抖 | 反向 12→**19**，比不加还差 —— **记为无效** |
| 2026-08-08 | 受击防抖 + 硬直抑制窗 | 防抖有效（§2.1）；抑制窗**帮了倒忙**（§2.2），当天回滚为 0 |

四轮的共同点不是想错了，是**没有尺子**：改完只能看经验增长这类间接指标，错了要很久才发现，抑制窗这轮更是靠事后翻 8000 拍日志才看出来它把问题放大了 4 倍。

本设计不修任何东西。它只造一件东西：**在决策日志里，把角色的真实朝向和我们的信念并排写出来。** 拿到这个数字之前，不动决策代码。

## 2. 证据（2026-08-08 实测）

数据源：`logs/ok-script.log`，`决策日志开关=True`，00:47–12:24，11953+ 决策拍 / 707 受击行。按 `farm_logic.py` 落盘时刻（10:26）与 GUI 重启（10:28:56）切分。

### 2.1 受击防抖有效，保留

| | 上线前（段0-6，5811s） | 上线后（段7-8，1309s） |
|---|---|---|
| 受击间隔 <1s 占比 | **55%**（325/594） | **0%**（0/123） |

此前 55% 的「受击」是血条渐变动画把一次掉血拆成多拍读数，每拍都作废一次朝向信念。这条改动是对的，与本设计无关，应独立提交。

### 2.2 硬直抑制窗把问题放大了 4 倍，已回滚

| | 段0-6（无抑制窗） | 段7-8（抑制窗 0.8s） | 抑制窗=0 对照 |
|---|---|---|---|
| 朝向未知占时间 | 5.6% | **23.3%** | **8.1%** |
| 受击→下次成功转向 中位 | 0.62s | **1.55s** | **0.70s** |
| 转向 决定→执行 | 85% | 59% | — |

机制（代码确定）：`farm_logic.facing_half_zone` 在 `facing is None` 时**原样返回整个对称区**；受击处理把 `_facing = None`；抑制窗又禁止转向 0.8s，于是「无信念裸奔」的时间被拉长——期间有向攻击区退化成对称区，照常按攻击键，朝实际朝向（多半背对刚打你的怪）开火。

抑制窗=0 的对照实验四条判据全过（判据事先写死，见 `scratchpad/verify_suppress0.py`），归因成立。**配置已改为 0，不要再打开。**

### 2.3 残留的洞（与本设计并列，不由本设计修）

抑制窗=0 之后，8020 决策拍中仍有：

- 朝向未知 **9.5%**（765 拍）
- 其中 可打=True、按对称区开火 **6.9%**（557 拍）
- 其中 88 拍区内左右都有怪 —— **必有一半目标在背后，确定性打空**

这是「受击清空 `_facing` → 有向攻击区退化成对称区」的直接残余，结构性的（受击到下一个决策拍有 ≤0.7s 窗口）。它已经被坐实，**不依赖本设计的结论就可以单独修**。

### 2.4 游戏机制（2026-08-08 由用户确认）

`2026-08-07-facing-reassert-on-hit-design.md` §3.4 把这三条挂了一整天「待验证假设，不许当结论用」。现在有答案了：

| 问题 | 答案 |
|---|---|
| 施法/攻击动画期间按方向键，角色会转吗？ | **不会，键直接丢失，动画结束也不补** |
| 魔法箭从按键到重新可操作多久？ | **约 0.7–1.0 秒** |
| 受击会不会把角色翻向攻击者？ | **不会，本来朝哪边就是哪边** |

配合实测：段7-8 中成功转向 196 次，**距上一次攻击键的中位间隔 0.55s**，40% 落在 0.4s 内，78% 落在 1.0s 内。而 `攻击间隔=0.7s` < 施法时长 0.7–1.0s。

结论：**两次攻击之间几乎没有真空窗，独立发出的转向 tap 绝大多数落在施法动画中段，必丢；而 `_facing` 照写 → 信念必定分叉。**

这条推论看起来很硬，但它**仍然只是推论**——我们从未观测过角色的真实朝向，不知道分叉实际发生了多少次。§7 的判据就是用来给它定量的，也用来证伪它。

### 2.5 仪器可行性

附录 A（2026-08-07，24 帧实测，本设计直接引用，不重测）：

| 指标 | 数值 |
|---|---|
| 判据 `max(s,s_flip) ≥ 0.70` 且 `\|s − s_flip\| ≥ 0.20` | **20/24 命中，0 误判，4 弃权** |
| 胜出分中位 / 差值中位 | 0.883 / 0.411 |
| 命中帧胜出分最低 / 弃权帧最高 | 0.78 / 0.45 |
| 命中帧差值最低 / 弃权帧最高 | 0.35 / 0.055 |
| 单帧开销 | 亚毫秒 |

4 个弃权帧全是宠物「小白雪人」挡住或角色被 ROI 切边。**弃权的全是真判不了的帧，没有一个自信的错误答案。**

锚点通道分布（2026-08-08 实测，8874 拍）决定了观测器能覆盖多少拍：

| 通道 | 占比 | 在「要转向」的拍里 |
|---|---|---|
| template | 38.3% | 32% |
| window | 30.5% | 33% |
| region | 2.2% | 3% |
| cached | 28.3% | 31% |
| fallback | 0.8% | 0% |
| **本拍真命中合计** | **71.0%** | **68.5%** |

`cached`/`fallback` 拍的锚点是沿用/外推的，ROI 会整体错位，这些拍不观测。配合 83% 的判定率，覆盖率约为「该转向的拍」的 57% —— 做纠正/度量足够，错了一两拍内就能抓住。

## 3. 设计

### 3.1 边界

| 文件 | 职责 |
|---|---|
| `src/detect/facing.py`（新增） | CV：裁 ROI、双向 matchTemplate、按判据出 `'LEFT'`/`'RIGHT'`/`None` |
| `src/task/farm_logic.py` | 纯判定：采模板的「走动确认」条件 |
| `src/task/MapleFarmTask.py` | 接线：何时观测、何时采模板、写日志 |

与 `anchor.py` / `bars.py` 同级，沿用现有结构：CV 归 `detect`，纯函数归 `farm_logic`，任务只接线。三者可独立测试。

**热重载注意**：`src/detect/facing.py` 与 `farm_logic.py` 都不参与热重载（`ok/gui/tasks/TaskManger.py` 只重载任务模块自身，不递归依赖）。改了必须重启 GUI，否则新任务代码 + 旧依赖 = `AttributeError`。2026-08-08 10:23 已经踩过一次。

### 3.2 观测判据

照抄附录 A，一个字不改：

- ROI：`x ∈ [a.x−90, a.x+90]`，`y ∈ [a.y−160, a.y−20]`（180×140），转灰度
- 对 ROI 跑两次 `cv2.matchTemplate(..., TM_CCOEFF_NORMED)`：一次用模板，一次用模板的水平镜像，取各自最大值 `s` / `s_flip`
- 判定：`max(s, s_flip) ≥ 0.70` **且** `|s − s_flip| ≥ 0.20`，否则返回 `None`（弃权）
- `s > s_flip` → 与模板同向；否则反向

阈值写成模块常量 `FACING_SCORE_MIN = 0.70`、`FACING_MARGIN_MIN = 0.20`，不暴露成配置——附录 A 的裕度很大（命中最低 0.78 vs 弃权最高 0.45），先不造旋钮。

ROI 越界（角色贴屏幕边缘）→ 返回 `None`，不抛。

### 3.3 模板从哪来：走动确认

模板自带一个朝向。`s > s_flip` 只说明「与模板同向」，要换算成 L/R 就必须知道模板本身朝哪边。

**不能用 `_facing` 标定**——那正是被检验的对象，拿它标定是循环论证。

采集条件（全部满足才采）：

| 门 | 条件 | 理由 |
|---|---|---|
| 正在寻怪长按 | `_seek_key is not None` | 寻怪是长按方向键连续走，方向明确 |
| 位移已确认 | 自本次长按按下那一拍记下 `body_x` 起算，沿按键方向累计移动 ≥ `FACING_CAPTURE_MIN_DX`（40px） | **这是位移观测，不是信念**：角色真的走了，就必定面朝那个方向 |
| 锚点是 OCR 完整命中 | 与 `_capture_nametag_template` 同一道门（`anchor` 结果带 `text`，部分匹配 `'ng咕咕'` 不算） | 附录 A.3：部分匹配的 OCR 框中心系统性右偏，裁出来的 ROI 是草地和宠物脸，实验会作废 |
| 还没有模板 | `_facing_template is None` | 只采一次，采到就复用 |

模板 = ROI 内的头+肩子框（58×66）。落盘到 `screenshots/facing_templates/{角色名}_L.png` 或 `_R.png`，后缀记采集时那次走动的方向，下次启动直接加载，不用重新等走动。

**子框在 ROI 内的偏移，附录 A 没有记下来**（A.1 只写了「取其中一帧的头+肩子框（58×66）作模板」，没给坐标）。实现时必须重新定：拿 `_frames_backup/` 的存档帧裁一次 ROI，目视定位头+肩在 180×140 内的位置，把偏移写成模块常量并在注释里记下是怎么定的。不要凭空猜一个数——A.3 的教训正是 ROI 取错就整个实验作废。

代价：启动后要等第一次寻怪走动才有模板。实测寻怪占 20–35% 的拍，几十秒内必然发生；此前观测字段一律 `?`。

附录 A.4 提过换装备/发型会让模板失效。只读阶段不处理——真失效了表现为弃权率飙升，日志里看得见。

### 3.4 接入点

在 `_detect_and_act` 里，**紧接在锚点解析之后、任何决策之前**观测一次：

```
anchor_hit, source = self._resolve_anchor(...)
observed = self._observe_facing(frame, anchor_hit, source)   ← 新增，只读
...（其余决策一个字不改）
```

门：

- `朝向观测开关` 为真（新配置，默认 **关**）
- `source in ('window', 'region', 'template')` —— `cached`/`fallback` 直接跳过
- `_facing_template is not None`

**观测结果不参与任何决策**，只进日志。异常一律吞掉并记 `_log_detect_error`（与 YOLO/模板匹配同样处理），观测器不能把挂机搞崩。

### 3.5 配置

| 键 | 默认 | 说明 |
|---|---|---|
| `朝向观测开关` | `false` | 只读排查用：每个锚点真命中的检测拍，用模板匹配读出角色**真实**朝向，与信念朝向一起写进决策日志。不影响任何决策，纯粹是尺子。开着会在没模板时先等一次寻怪走动来采模板。排完记得关 |

## 4. 可观测性

决策行末尾加两个字段（受现有 `决策日志开关` 控制，与 `朝向观测开关` 同时为真才写）：

```
实测=L|R|?  分值=0.88/0.41
```

- `实测` = 观测结果，`?` = 弃权或未观测
- `分值` = `胜出分/差值`，用来事后判断阈值定得合不合适

信念与实测**分歧**时，额外单独写一行，便于 `grep`：

```
朝向分歧 信念=RIGHT 实测=LEFT 分值=0.86/0.39 距上次攻击=0.42s 距上次受击=3.10s 距上次转向=1.55s
```

那三个「距上次」是 §5.4 判据 D 的数据源——用来判断分叉到底集中在施法窗、硬直窗，还是均匀分布。少任何一项就只能靠猜。

**读这个字段时注意**：`_last_turn` 在受击处理里被重置为 `0.0`（哨兵），所以受击之后、下一次成功转向之前，`距上次转向` 会显示成一个巨大的值，不是真的那么久没转。判据 D 只用 `距上次攻击` 分桶，不受影响；但人工看序列时别被这一项误导。

## 5. 验证计划（判据事先写死）

### 5.1 纯函数单测（`tests/test_farm_logic.py`、`tests/test_facing.py`）

`facing.decide(s, s_flip, template_facing)`：
- `s=0.88, s_flip=0.47`（差值 0.41）→ 与模板同向
- `s=0.47, s_flip=0.88` → 与模板反向
- `s=0.45, s_flip=0.40`（胜出分 < 0.70）→ `None`
- `s=0.85, s_flip=0.80`（差值 0.05 < 0.20）→ `None`
- `template_facing='LEFT'` 时同向 → `'LEFT'`；反向 → `'RIGHT'`

**不测阈值精确边界**：`0.70` / `0.20` 在 IEEE754 下的边界断言会随字面量写法漂移（`2026-08-07` 那份 spec §7.1 已经在 `hp_drop` 上踩过同样的坑）。测明确在两侧的值即可。

`farm_logic.walk_confirmed(seek_dir, body_x_start, body_x_now, min_dx)`：
- `seek_dir='right'`，位移 +45（≥40）→ True
- `seek_dir='right'`，位移 +30 → False
- `seek_dir='right'`，位移 **−45**（按右键却往左动 = 撞墙/锚点跳变）→ False
- `seek_dir=None` → False

### 5.2 CV 层回归（`tests/test_facing.py`）

`dataset/raw/` 在 `.gitignore` 里，附录 A 那 24 帧的判别基线**进不了仓库**。回归只能用：

- 合成图：一张不对称的小图当模板，构造同向/镜像/噪声三种 ROI，验证 `decide` 的接线
- `_frames_backup/training_ground_full_2560x1440.png`：验证 ROI 裁剪几何与越界处理不抛

**跑测试前必须确认 `screenshots/test_frames/` 是目录且含 `training_ground_full_2560x1440.png`**（每次跑 GUI 都会把这个路径当截图文件名写掉，备份在 `_frames_backup/`）。否则 30+ 用例批量假失败，与本改动无关。

### 5.3 任务级离线测试（`tests/test_farm_task_offline.py`）

- `朝向观测开关=false` → `_observe_facing` 零调用，决策行**逐字符**与改动前一致
- `source='cached'` → 不观测，字段为 `?`
- `_facing_template is None` → 不观测，且满足走动确认时会采一次
- 观测抛异常 → 不传播，决策照常完成
- **观测结果不写 `_facing`**（本设计的核心约束，必须有断言守着）

几何前提照 memory：`DEFAULT_CONFIG['角色名']` 是空串 → 锚点回退画面中心 (1280,720)、身体 (1280,630)。测试里 patch `find_in_region` 是无效的（走不到那条通道）。

### 5.4 实弹判据（管理员提权 + 游戏前台，2560×1440）

开 `决策日志开关` + `朝向观测开关`，同一地图挂 **≥20 分钟**。

**判据 A（仪器可用）**——不过则 B/C/D 全部无意义，不许解读：
- 在「锚点真命中 且 已有模板」的拍里，观测给出答案（非弃权）的比例 **≥ 50%**
- 低于 50% → 先修仪器（模板质量 / ROI / 阈值），不许拿分叉率下任何结论

**判据 B（无随机噪声）**——自洽性检查，抓的是「仪器在乱答」：
- 在「相邻两拍都给出答案 且 期间没有发出任何方向键」的拍对里，观测朝向翻转的比例 **≤ 5%**
- 超了说明观测在抖，B 不过同样不许解读 C

**判据 C（分叉率，主结果）**：
- 在「锚点真命中 且 观测非弃权 且 `_facing` 非 None」的拍里，`实测 != 信念` 的比例

事先写死的决策线：

| 分叉率 | 结论 | 下一步 |
|---|---|---|
| **≥ 10%** | §2.4 的吞键推论坐实 | 做「动画忙窗」（§6），本观测器转为它的验收仪器 |
| **3% – 10%** | 灰区 | 看判据 D 的时间相关性再定 |
| **< 3%** | 吞键推论**证伪** | 动画忙窗**不做**。只修 §2.3 那个已坐实的独立洞，然后回 Phase 1 重查症状 |

**判据 D（时间相关性）**——分叉率落在灰区时用它裁决，落在其它区间时用它交叉验证：
- 把分歧拍按「距上次攻击键」分桶
- 若 `[0, 1.0s]` 桶（= 施法窗内）的分叉率 **≥ 其余桶的 2 倍** → 吞键机制坐实，做动画忙窗
- 若分叉在各桶均匀分布 → 不是施法吞键，另有原因，回 Phase 1

## 6. 下一步（本设计不实现）

用户提出的**动画忙窗模型**，等判据 C/D 的数据再决定做不做：

维护 `_busy_until`：发出攻击键 → `now + 施法时长`；检测到受击 → `now + 硬直时长`（**覆盖，不取 max**——受击会打断施法，原来的施法窗作废）。方向键与攻击键都只在 `now >= _busy_until` 时发出。

这样盲写 `_facing` 只发生在游戏确定空闲的时刻，键必落地，信念分叉从源头消失；转向 tap 的频率和左右轮换特性都不变，**不引入 50ms 轻点的累积位移**（这是「每次攻击都重发方向键」那个方案被否掉的原因）。顺带把「`攻击间隔=0.7s` 短于施法时长导致的空按」一起修掉。

已知短板：它是**开环**的，推算而不观测，任何没建模的忙碌来源都会让它悄悄失准且无信号。这正是要先有本观测器的原因。

## 7. 明确不做

- **让观测驱动决策** —— 本轮纯只读。观测器自己都还没被验证过，先让它证明自己看得准
- **多姿态模板库** —— 附录 A.3 已证明头+肩单模板跨动画姿态就够（拿盾、挥杖 0.82–0.89 照样命中）
- **在 `cached`/`fallback` 拍上观测** —— ROI 会整体错位，宁可少 29% 的样本，不要脏数据
- **给弃权加重试 / 放宽阈值凑覆盖率** —— 弃权是这个仪器最值钱的性质（附录 A：0 误判）。宁可少答，不许答错
