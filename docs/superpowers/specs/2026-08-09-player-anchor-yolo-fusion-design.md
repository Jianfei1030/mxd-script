# 怪堆丢锚治理 —— YOLO player 类 + 名字牌身份融合（2026-08-09）

> 现象（用户报告，场景选择 A）：**「怪堆里打着打着绿框冻住/漂走」**。
> 结论：角色定位只有名字牌一个信号源，而名字牌天生脆弱（常驻宠物牌 + 怪/路人牌遮挡）。
> 给现有 YOLO 检测加 **class 1 = player**（同一次推理，零额外开销）作为遮挡免疫的第二信号源；
> 「哪个 player 是我」的身份问题仍由名字牌通道校准，YOLO 只在名字牌失效的拍接管位置。

## 1. 现状与根因

### 1.1 现状阶梯

`MapleFarmTask._resolve_anchor`（`MapleFarmTask.py:385`）按阶梯取锚点：

模板分片匹配（`anchor.split_match`）→ 快窗 OCR（`anchor.find_in_window`，±240/±80）→
慢扫 OCR（`anchor.find_in_region`，受 `锚点刷新间隔(秒)`=2 节流）→
cached 外推（`锚点保鲜(秒)`=10 内，寻怪中按 vx 外推）→ fallback（屏幕中心 x + 最后已知层高 y）。

四级全部依赖**名字牌可读**；cached/fallback 两级没有任何观测，是「绿框冻住/漂走」的直接来源。

### 1.2 实测证据（logs 在 .gitignore，只存本机；判据命令见 §1.3）

`ok-script.2026-08-08.log` 全天 **50265 决策拍**（约 9.8 小时）：

| src | 拍数 | 占比 |
|---|---|---|
| template | 20267 | 40.3% |
| window | 14544 | 28.9% |
| region | 1122 | 2.2% |
| **cached** | **13454** | **26.8%** |
| **fallback** | **878** | **1.7%** |

- **丢锚拍（cached+fallback）= 28.5%**；交叉验证 `baseline-2026-08-08-seek.log`（30584 拍）= 26.3%，方向一致
- 丢锚段 **6087 段 / 累计 8898s（约占挂机时长 25%）**，中位 0.69s（外推兜得住），**p90 2.19s，≥3s 的 325 段（≈33 段/小时）**——长尾才是伤效率的部分
- 战斗内外丢锚率 **31.6% vs 26.8%**，各 src 的平均屏怪数 3.2~4.3 无显著差——
  说明主遮挡源是**常驻**的（宠物「小白雪人」的牌子永远跟着角色），怪堆只是雪上加霜
- 慢扫仅占 2.2%：丢锚常由位置跳变（击退）触发，而慢扫被 2s 节流卡在最需要它的时刻


## 2. 方案选型（含被否项）

| 方案 | 判定 | 理由 |
|---|---|---|
| **YOLO 加 player 类 + 名字牌身份融合** | **选定** | 检测角色本体而非名字牌，任何牌子遮挡都不影响；复用每拍已有的推理（~22ms），零额外延迟；训练全链路（标注/预标/训练/部署）AGENTS.md §2-3 现成 |
| 事件触发即时慢扫 | 捎带做 | 改动很小，治「击退跳变后慢扫被节流卡 2s」，见 §3.5 |
| 小地图黄点定位 | 推迟 | 治地图边缘/全局定位，不治怪堆遮挡（用户场景 A）；留作将来巡逻/换图特性的地基 |
| 快窗渐进放大 / 多模板库 | 暂缓 | 先看 YOLO 层把丢锚压到多少，不够再加（YAGNI） |
| 内存读取 | 永不 | 项目是纯像素观测路线（AGENTS.md §7.4 同一立场） |

当初不加 player 类的理由（`anchor.py:4`「会把长得一样的别的玩家认成自己」）由融合层解决：
YOLO 学「什么是玩家」，名字牌通道学「哪个是我」，各干各的。

## 3. 设计

### 3.1 类别语义与数据

**class 1 = 任意玩家角色**（不是「只有我」）。YOLO 学不会身份，硬教（只标自己）会把
同屏路人变成标注噪声；分辨自己是融合层（§3.3）的职责。宠物不算 player（外观差异大，
且宠物牌正是要绕开的遮挡源）。

改动点：
- `dataset/mobs.yaml`：`names` 加 `1: player`
- `src/OpenVinoYolo8Detect.py:15`：`dic_labels = {0: 'mob', 1: 'player'}`
- `scripts/label_boxes.py`：加类别切换键（现在写死 class 0），框上色区分
- `scripts/prelabel_from_onnx.py`：首轮训练后可用新模型预标 player，减轻后续标注

数据增量（关键）：现有 270 帧原始数据全是巡逻帧（当时采集规范明确「不攻击」），
而本次要治的恰是**战斗中被围**——必须补采实战帧：

- 挥砍特效/伤害数字盖身、被击退、坐椅、怪压身，各姿态都要有，预计 **100-200 帧**
- **有路人/队友同屏的帧**（让模型把别人也框出来，融合层才有东西可拒绝）
- 给现有 70 张 train/val 图补标 player 框（角色几乎每帧都在画面里）

训练回归门（防「加类别把找怪弄坏」）：
- mob 类 val 指标**不得低于现役模型**（对照 `dataset/runs/` 里现役训练的 val 结果）
- player 类 **mAP50 ≥ 0.90**
- 部署前按惯例备份旧 onnx（AGENTS.md §3.4）

### 3.2 一拍一次推理与分流

`OpenVinoYolo8Detect.detect` 每次调用都是完整推理（`label` 只是 `_postprocess` 里的
事后过滤，`OpenVinoYolo8Detect.py:99`），分两次调用会白付一倍推理。改成：

- `_detect_and_act` 开头调一次 `og.my_app.yolo_detect(frame, threshold, label=-1)`，
  按 `Box.name` 分流：`mobs = [b for b in boxes if b.name == 'mob']`、
  `players = [b for b in boxes if b.name == 'player']`
- 现有 `find_mobs` 调用点（`MapleFarmTask.py:586`）改用分流结果，找怪行为不变；
  try/except 包住统一调用，异常时 mobs/players 都取空（沿用现有降级路径）
- `BaseMapleTask.find_mobs(label=0)` 保留，WarriorDebugTask 等调用方不动
- 阈值：player 与 mob 共用现有检测阈值（0.5），不加独立旋钮，数据说需要再加
- `_resolve_anchor(frame, now, cfg)` 签名加一个参数 → `_resolve_anchor(frame, now, cfg, players)`

### 3.3 阶梯插层与关联规则（核心）

新阶梯：**模板 → 快窗 OCR → 【新增】YOLO 关联 → 慢扫 OCR → cached → fallback**。

放在两条名字牌通道**之后**是有意的：名字牌可读时身份持续刷新；若放在最前，
快窗 OCR 永远轮不到，身份就再也不校准，关联错一次会一路错下去。
YOLO 级只接管名字牌失效的拍——正是遮挡拍。

关联规则，纯函数 `farm_logic.select_player_box(players, pred, identity_fresh)`：

- `pred` = 与快窗 OCR 同一个搜索中心：（`_extrapolated_anchor_x(now, cfg)`，上次锚点 y），
  即 `MapleFarmTask.py:407-408` 已有的 `center`，不新造第二套外推
- 门内候选 = 框中心**换算到名字牌坐标系后**落在 `pred` 的
  **±PLAYER_GATE_HALF_W(240) / ±PLAYER_GATE_HALF_H(120)** 内
  （纵向比快窗的 80 放宽：击退/跳跃纵向位移大，快窗为 OCR 成本收窄的理由对免费的 YOLO 不成立）
- **坐标系必须换算**（2026-08-09 实测修正，初版漏了这步）：`pred` 是名字牌坐标
  （`self._anchor` 存的一直是名字牌 y），YOLO 框中心却在身体上。实测框中心比名字牌
  高 `PLAYER_BOX_TO_NAMETAG = 64px`（403 组「相邻拍 + 角色几乎没动」的 yolo↔名字牌
  配对，p10 61 / p90 67）。不换算直接比，±120 的门实际变成 **上 56px / 下 184px**：
  自己一跳（>56px）就被踢出门 → 丢锚；同时下一层平台的路人稳稳落在门内，
  在自己没被检出的拍里成为**唯一候选**被无条件接受 → 认错人。
  唯一事实源 `farm_logic.player_box_anchor(box)`，门与「取最近」共用
- **门随「距上次真观测的时长」缩放**（2026-08-09 实测补强，`player_gate_size(dt)`）：
  `min(上限, base + 极速 × dt)`，`dt = now - _last_anchor_hit`。固定 ±240 对相邻拍宽得
  离谱——0.2s 里角色最多走 60px，门却容得下 240px 外的路人；自己那拍没被检出时
  （YOLO 单帧漏检、被自己的攻击特效盖住），路人就是门内**唯一**候选，直接被无条件接受。
  相邻拍（dt≈0.2s）收到 ~170×110。常数由实测定：关联距 p99 对 dt 线性拟合斜率
  ~260px/s（取 300 放宽），dt<0.15s 的 max=174px 是击退冲量（base_w=110 覆盖）；
  纵向相邻拍 |Δanchor_y| p50=2 / p99=62 / max=66（base_h=70 覆盖）。
  **上限保留是必须的**：dt 到几秒时角色可能已经跑到任何地方，门再放大等于「谁都能
  认成自己」，那时该交给慢扫验名（§3.7），不是靠更宽的门去猜
- 恰 1 个 → 接受
- 多个 → `identity_fresh`（距上次名字牌真实命中 ≤ `身份保鲜(秒)`，默认 10）时取最近者，
  否则**拒绝**（路人贴身且身份过期，宁可退到慢扫/cached，不认错人）
- 0 个 → 落到下一级
- **冷启动不参与**：`self._anchor is None`（还没有任何名字牌命中）时跳过 YOLO 级——
  没有先验位置就没有门，首个身份必须由慢扫 OCR 建立

### 3.4 伪锚点与状态联动

命中的 player 框换算成伪锚点，下游全部不用改：

```python
Anchor(*farm_logic.player_box_anchor(box), box.width)
# = Anchor(box中心x, box中心y + PLAYER_BOX_TO_NAMETAG(64), box.width)
```

伪锚点存的是**名字牌位置**——`_anchor` 全程只有这一种坐标系，下一拍的 OCR 小窗、
模板窗、关联门都按它定心。

初版这里写的是 `+ cfg['名字牌到身体偏移(像素)']`（88），把两个不同的量混用了：
88 是「名字牌 → 攻击落点（肩/手高度）」的标定值，64 是「框中心 → 名字牌」的实测
几何。后果有二：① 关联门整体偏 64px（见 §3.3）；② yolo 拍的 `anchor_y` 比名字牌拍
系统性低 88−64 = 24px（实测中位 24 / p10 21 / p90 27），来源每翻一拍攻击区就上下抖
24px。换算成 64 后，`anchor.body_center()` 得到的落点与名字牌拍完全一致。

状态联动：
- 伪锚点喂 `_update_anchor`：学 vx、更新 `_last_anchor_hit`（它是真实观测）、
  给下一拍模板/OCR 窗口定中心——**遮挡一散，名字牌通道就在正确位置重新咬住并刷新身份**
- **身份时间戳单独记**：新增 `_last_identity_hit`，只有 **window/region** 刷新（真读到名字）；
  yolo 不刷新（它不验名）。**template 也不刷新**（2026-08-09 修正）——初版把它算作验名是错的：
  模板是**像素**匹配，命中的 `AnchorHit.text` 是空串，从头到尾没读过名字。让它刷新的后果是
  一次误匹配就把 §3.7 的复验永久锁死，见 §3.8
- 朝向模板采集与朝向观测的来源门维持 `('window', 'region', 'template')` 不变
  （`MapleFarmTask.py:374`），yolo 天然被排除，不引入新的 ROI 错位风险
- 来源标签 `src=yolo`，决策日志自动带出
- 总开关 `YOLO角色定位开关`（默认开）；关掉 = 完全旧阶梯

### 3.5 事件触发即时慢扫（捎带）

触发条件：本拍模板、快窗、YOLO 三级全失，**且**（本拍 `knockback_detected` 触发过
或 锚点年龄 > `锚点刷新间隔(秒)`）→ 立刻跑一次慢扫，绕过 2s 节流。

- 强制扫描自身限频：`FORCED_RESCAN_MIN_INTERVAL = 0.5s`（慢扫最坏 235ms，不许打满主循环）
- 实现：`farm_logic.should_rescan_anchor` 加 `force` 参数（保持纯函数可测）
- 开关 `丢锚立即重扫开关`（默认开）；关掉 = 旧节流行为

### 3.7 身份复验慢扫（2026-08-09 补，修「认错人之后回不来」）

初版把 YOLO 级插在慢扫**之前**，但漏了一件事：YOLO 级一命中就 `return`，
排在它后面的慢扫**根本轮不到**。实测后果：

- 慢扫占比 2.2%（8-08 基线）→ **0.6%**——唯一验名通道被饿死
- YOLO 认错人后 `_update_anchor` 照样刷新 `_anchor_time`、清掉 `_force_rescan`，
  §3.5 的丢锚立即重扫也不会触发
- `_last_identity_hit` 过期只拦**多候选**，拦不住单候选 → 锚点永久钉在路人身上。
  实测 22 段 yolo 自始至终没被名字牌接住（最长 67 拍 / 25.5s）；慢扫一旦跑起来
  就把锚点拉走 >400px 的比例从 3% 涨到 12%

规则：**身份过期时，慢扫排到 YOLO 级之前**。

- 触发：名字牌两级本拍都失效 **且** `not identity_fresh` **且** 距上次复验 ≥
  `身份复验间隔(秒)`（默认 3）
- 扫不到 → 照常落到 YOLO 级。复验只加验名机会，**绝不新增丢锚**
- 一拍只许一次慢扫：复验那次同时记 `_last_anchor_scan` / `_last_forced_rescan`，
  并消费 `_force_rescan`——受击想要的那次慢扫已经发生了
- `身份复验间隔(秒)` 同时是**「认错人最长持续时间」的上界**
- 实现共用 `_scan_region()`（命中后更新锚点 / 刷身份 / 裁模板的记账只此一份，
  两个调用点各抄一遍迟早分叉，身份时间戳漏刷一处等于验名失效）
- 开关 `身份复验开关`（默认开）；关掉 = 旧阶梯

### 3.8 模板棘轮漂移（2026-08-09 实测，「飘到半空中再也回不来」根因）

用户报「锚点飘到半空，一直在同一平面打怪却再也回不来」。日志坐实，**与 YOLO 无关**：

- 全天 17048 个决策拍里，**11.6%（1970 拍）锚点飘在平台上方 >80px**，其中
  **90%（1775 拍）由 `template` 持有**；template 拍的 `anchor_y` p1 = **19**（屏幕顶）
- 逐拍轨迹是完美的等差数列：`887 → 837 → 775 → 713 → 651 → 589`，**每拍恒定 −62px**
- 62 不是巧合：`half_h - 模板高/2 = 80 - 36/2 = 62.0`。命中回推的
  `y = (cy - half_h) + ly + th/2`，只有 `ly = 0`（匹配落在搜索窗**顶边**）才给出 −62

机制 = **无人监督的正反馈**：模板通道把自己上一拍的输出当作下一拍的搜索中心，
一次误匹配 → 窗口跟着上移 → 下一拍在新窗口顶边再匹配一次 → 棘轮式爬升，
直到飞出屏幕。逃不掉是因为：模板排在阶梯**最前**且一命中就 `return`，
下面的 OCR/慢扫全部轮不到；而它还刷新 `_last_identity_hit`，
连 §3.7 的复验都被永久压住。实测最长一段锚点在半空待了 **31 分钟**。

（补：`TM_SQDIFF_NORMED` 在全黑/稀疏窗口上的数值退化已排除——合成用例实测得分
恒为 1.0，会被 `not (score <= threshold)` 正常拒绝。问题不在数值，在**反馈结构**。）

两条修复，各管一半：

1. **纵向合理性帽子** `farm_logic.template_hit_plausible(hit_y, prev_y)`，
   `TEMPLATE_MAX_DY = 45`。依据：只取 OCR 验名过的相邻拍（n=2164），真实
   |Δy| p50=2 / p99=26 / p99.9=34，>40px 的只有 1 拍（0.05%）。
   日志复算：全天 48 次「飘到半空」的进入拍，**38 次（79%）当场挡下**；
   误伤 234/6210 = 3.8% 的 template 拍，而被挡下的那拍**不丢锚**——落到验名的
   OCR 快通道，弱证据本来就不该有重定义 y 的权力
2. **template 不再刷新身份时间戳**（见 §3.4）。剩下 21% 以小步长慢慢爬的漂移，
   由此在 `身份保鲜(秒)` 后触发 §3.7 复验慢扫拉回来 —— 把「再也回不来」
   从**无上界**变成 `身份保鲜 + 身份复验间隔` ≈ **13 秒**

| `身份保鲜(秒)` | 10 | 多候选时允许「取最近」的身份新鲜窗口 | 调小 = 收紧防误认 |

| `身份复验开关` | True | 身份过期时慢扫提到 YOLO 级之前验名（§3.7） | 关 = 旧阶梯 |
| `身份复验间隔(秒)` | 3 | 复验限频，也是「认错人最长持续时间」上界 | 调小 = 纠错更快、更吃 CPU |

模块常量（不进配置）：`PLAYER_GATE_HALF_W = 240`、`PLAYER_GATE_HALF_H = 120`（门的上限）、
`PLAYER_GATE_BASE_W = 110`、`PLAYER_GATE_BASE_H = 70`、`PLAYER_GATE_SPEED_X = 300`、
`PLAYER_GATE_SPEED_Y = 200`（时间缩放，§3.3）、`PLAYER_BOX_TO_NAMETAG = 64`（坐标系换算，
实测；**不是**配置里的 `名字牌到身体偏移(像素)=88`）、`TEMPLATE_MAX_DY = 45`（模板纵向
帽子，§3.8）、`FORCED_RESCAN_MIN_INTERVAL = 0.5`。

## 7. 测试

单测（离线，不依赖模型，铁律 §11.2）：

- GUI 启动、任务注册无回归
- 怪堆实战 ≥20 分钟：overlay 绿框不冻、不漂，遮挡时跟着角色本体走
- **站在路人/队友旁边实战**：绿框不跳到别人身上

## 8. 不做什么

- **不做小地图定位**——治的是边缘/全局，不是怪堆遮挡；留作巡逻特性地基
- **不做快窗渐进放大 / 多模板库**——先看 YOLO 层压掉多少，不够再加
- **不动 WarriorDebugTask 的锚点逻辑**——调试任务，不影响挂机；它自己的 `find_mobs(label=0)` 语义不变
- **不加 player 独立检测阈值**——与 mob 共用 0.5，数据说需要再加
- **不读内存**——纯像素观测路线不变
