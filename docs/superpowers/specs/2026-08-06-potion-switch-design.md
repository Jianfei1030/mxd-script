# 喝药总开关 —— 一键关闭自动回血/回蓝

日期：2026-08-06
状态：设计已确认，待实现
上游：`2026-08-05-ok-mxd-design.md`（MVP 设计，§7 异常处理）；承接 `2026-08-06` 已合并的喝药窗口判定修复（误停修复，本设计在其上叠加）

## 1. 问题

挂机时自动喝血/喝蓝是常开的，但某些场景用户想完全关掉自动用药（例如靠宠物自动喝药、手动接管蓝药），现在没有开关。

用户已确认的需求：

- **一个总开关**同时控制回血和回蓝（不做血/蓝分开）
- 关闭后，HP 低于 `保命血线` 的紧急分支**不再按血药键**，但回城卷（若配置）和停任务照常执行
- 默认**开**，与现状行为完全一致

## 2. 现状盘点

`src/task/MapleFarmTask.py` `run()` 里与用药相关的分支：

| 步骤 | 位置 | 行为 |
|---|---|---|
| 1. 保命 | `MapleFarmTask.py:203-213` | HP < `保命血线`(0.25)：按血药键 → 回城卷(若配置) → 停任务 |
| 2. 喝血 | `MapleFarmTask.py:214-235` | HP < `喝血阈值`(0.7)：按 1s 窗口喝药 + 「连续喝药无效」检测 |
| 3. 喝蓝 | `MapleFarmTask.py:236-238` | MP < `喝蓝阈值`(0.35)：按蓝药键 |
| 3.5. 药水耗尽保护 | `MapleFarmTask.py:240-249` | 每 `药水检查间隔(秒)`(30s) OCR 快捷栏，空槽则停任务 |

代码库已有布尔开关的先例，均采用「任务内内联门控」模式：

- `'拾取开关'` —— 作为参数传进纯函数 `farm_logic.should_pickup(now, last, interval, 开关)`
- `'走位开关'` —— 任务内 `if cfg['走位开关'] and ...` 直接门控

## 3. 设计

### 3.1 配置

新增 `DEFAULT_CONFIG` 键：

| 键 | 默认 | 说明 |
|---|---|---|
| `喝药开关` | `True` | 总开关，同时控制回血与回蓝 |

注册 `config_description`（GUI 悬浮说明）。

### 3.2 门控行为

`run()` 中按 `'走位开关'` 的既有内联模式：

- **关**：
  - 步骤 2（喝血）、3（喝蓝）、3.5（药水耗尽保护）整段跳过 —— 不按血/蓝药键、不 OCR 快捷栏、不跑「连续喝药无效」检测
  - 步骤 1（保命）不按血药键，但回城卷（若配置）与停任务照常
- **开**：与现状逐字节一致，现有测试全部不动

攻击、拾取、走位、死亡判定、画面静止/经验停滞守卫**不受影响**。

### 3.3 实现点

1. `DEFAULT_CONFIG` 加 `'喝药开关': True`；`config_description` 加说明
2. `run()`：
   - 步骤 1：`self.send_key(keys['血药键'])` 外包 `if cfg['喝药开关']:`
   - 步骤 2/3/3.5：整段包进 `if cfg['喝药开关']:`
3. 测试（见 §4）

不做任何 farm_logic 改动 —— 开关只是布尔门控，不参与纯函数决策。

## 4. 验证计划

`tests/test_farm_task_offline.py` 新增：

- 关开关 + HP 低于 `喝血阈值` → 不按 `血药键`，不触发「连续喝药无效」停止
- 关开关 + MP 低于 `喝蓝阈值` → 不按 `蓝药键`
- 关开关 + HP 低于 `保命血线` + 已配回城卷 → 不按 `血药键`，但按回城卷并停任务
- 开开关（默认）→ 现有用例原样全绿，无需改动

## 5. 明确不做

- 血/蓝分开的开关（用户已选总开关）
- 按地图/按血量条件自动切换开关（YAGNI）
- 关开关时对「喝药无效」「药水耗尽」的静默告警（开关关了就是不要这些行为）
